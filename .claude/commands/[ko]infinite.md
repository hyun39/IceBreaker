**무한 에이전트 루프 명령**

이 무한 생성 작업을 깊이 생각하세요. 곧 정교한 반복적 창작 과정을 시작합니다.

**변수:**

spec_file: $ARGUMENTS
output_dir: $ARGUMENTS
count: $ARGUMENTS

**인자 파싱:**
"$ARGUMENTS"에서 다음 인자를 파싱합니다:
1. `spec_file` — 마크다운 사양 파일 경로
2. `output_dir` — 반복 결과가 저장될 디렉터리
3. `count` — 반복 횟수 (1–N 또는 "infinite")

**1단계: 사양 분석**
`spec_file`의 사양 파일을 읽고 깊이 이해합니다. 이 파일은 다음을 정의합니다:
- 어떤 유형의 콘텐츠를 생성할지
- 형식 및 구조 요구사항
- 구체적인 매개변수나 제약
- 반복 간 의도된 진화 패턴

사양의 의도와 각 반복이 이전 작업을 어떻게 발전시켜야 하는지 신중히 고려합니다.

**2단계: 출력 디렉터리 정찰**
`output_dir`를 철저히 분석하여 현재 상태를 파악합니다:
- 기존 파일 전체와 이름 규칙 나열
- 현재까지 가장 높은 반복 번호 확인
- 기존 반복에 걸친 콘텐츠 진화 분석
- 이전 생성들의 궤적 이해
- 새 반복을 위한 공백이나 기회 파악

**3단계: 반복 전략**
사양 분석과 기존 반복을 바탕으로:
- 시작 반복 번호 결정 (기존 최대값 + 1)
- 각 새 반복이 어떻게 독특하고 진화적으로 이어질지 계획
- 신선함을 유지하면서 이전 반복을 어떻게 쌓을지 고려
- count가 "infinite"이면 컨텍스트 한계까지 지속 생성 준비

**4단계: 병렬 에이전트 조율**
효율과 창의적 다양성을 위해 여러 하위 에이전트를 배치해 반복을 병렬로 생성합니다:

**하위 에이전트 분배 전략:**
- count 1–5: 모든 에이전트 동시 기동
- count 6–20: 조율을 위해 5명 단위 배치 기동
- "infinite": 3–5명 물결(wave)로 기동, 컨텍스트를 모니터링하며 새 물결 생성

**에이전트 할당 프로토콜:**
각 하위 에이전트는 다음을 받습니다:
1. **사양 컨텍스트**: 사양 파일 분석 전체
2. **디렉터리 스냅샷**: 기동 시점의 `output_dir` 현재 상태
3. **반복 할당**: 구체적인 반복 번호 (시작 번호 + 에이전트 인덱스)
4. **유일성 지시**: 기존 반복과 개념이 겹치지 않도록 하는 명시적 지침
5. **품질 기준**: 사양에서 오는 상세 요구사항

**에이전트 작업 사양:**
```
작업: [OUTPUT_DIR]에서 [SPEC_FILE]에 대한 반복 [NUMBER] 생성

당신은 반복 [NUMBER]를 생성하는 하위 에이전트 [X]입니다.

컨텍스트:
- 사양: [전체 사양 분석]
- 기존 반복: [현재 output_dir 내용 요약]
- 당신의 반복 번호: [NUMBER]
- 할당된 창의 방향: [탐구할 구체적 혁신 차원]

요구사항:
1. 사양을 완전히 읽고 이해할 것
2. 출력이 유일하도록 기존 반복을 분석할 것
3. 사양 형식을 정확히 따른 콘텐츠를 생성할 것
4. 사양 준수를 유지하면서 [할당된 혁신 차원]에 집중할 것
5. 지정된 이름 규칙과 정확히 일치하는 파일 생성
6. 반복이 실질적인 가치와 참신함을 더하는지 확인할 것

산출물: 지정된 단일 파일, 유일하고 혁신적인 콘텐츠
```

**병렬 실행 관리:**
- Task 도구로 할당된 모든 하위 에이전트를 동시에 기동
- 에이전트 진행과 완료 모니터링
- 에이전트 실패 시 반복 번호 재할당으로 처리
- 중복 반복 번호가 생성되지 않도록 보장
- 완료된 모든 반복을 수집하고 검증

**5단계: 무한 모드 오케스트레이션**
무한 생성 모드에서는 연속적인 병렬 물결을 조율합니다:

**물결 기반 생성:**
1. **물결 계획**: 컨텍스트 여유에 따라 다음 물결 규모(3–5 에이전트) 결정
2. **에이전트 준비**: 각 새 물결에 맞는 최신 컨텍스트 스냅샷 준비
3. **점진적 정교화**: 각 물결은 더 발전된 혁신 차원을 탐구해야 함
4. **컨텍스트 모니터링**: 모든 에이전트와 메인 오케스트레이터의 총 컨텍스트 사용량 추적
5. **정상적 종료**: 컨텍스트 한계에 가까우면 현재 물결을 마치고 요약

**무한 실행 사이클:**
```
WHILE context_capacity > threshold:
    1. 현재 output_dir 상태 평가
    2. 남은 컨텍스트에 따라 다음 에이전트 물결 규모 계획
    3. 점점 더 정교한 창의 방향 할당
    4. 병렬 하위 에이전트 물결 기동
    5. 물결 완료 모니터링
    6. 디렉터리 상태 스냅샷 갱신
    7. 남은 컨텍스트 용량 평가
    8. 용량이 충분하면 다음 물결로 계속
    9. 한계에 가까우면 마지막 물결을 완료하고 요약
```

**점진적 정교화 전략:**
- **물결 1**: 단일 혁신 차원으로 기본적 기능적 대체
- **물결 2**: 향상된 상호작용을 가진 다차원 혁신
- **물결 3**: 적응적 동작을 포함한 복합 패러다임 조합
- **물결 N**: 사양의 경계를 밀어붙이는 혁신적 개념

**컨텍스트 최적화:**
- 각 물결은 컨텍스트 누적을 피하기 위해 새 에이전트 인스턴스 사용
- 메인 오케스트레이터는 가벼운 상태 추적만 유지
- 컨텍스트 관리를 위해 완료된 반복의 점진적 요약
- 후반 물결에서 덜 중요한 세부는 전략적으로 축소

**실행 원칙:**

**품질과 유일성:**
- 각 반복은 실질적으로 유일하고 가치 있어야 함
- 이전 작업을 바탕으로 하되 새로운 요소 도입
- 원본 사양과의 일관성 유지
- 파일 구성과 이름 규칙을 올바르게 유지

**병렬 조율:**
- 창의적 다양성을 최대화하도록 하위 에이전트를 전략적으로 배치
- 겹침을 피하기 위해 각 에이전트에 서로 다른 혁신 차원 할당
- 파일 이름 충돌을 막기 위한 타이밍 조율
- 모든 에이전트의 성공적 완료와 품질 모니터링

**확장성과 효율:**
- 병렬 스트림에 걸친 진화 궤적을 깊이 고려
- 무한 모드에서는 컨텍스트 소진 전 최대한 유용한 산출을 목표로 함
- 물결 기반 생성으로 컨텍스트 한계를 지능적으로 관리
- 병렬 속도와 품질·조율 오버헤드의 균형

**에이전트 관리:**
- 각 하위 에이전트에 완전한 컨텍스트와 명확한 할당 제공
- 반복 재할당으로 에이전트 실패를 우아하게 처리
- 모든 병렬 출력이 전체 진행과 응집되게 맞물리도록 보장

**초심층 사고 지시:**
생성을 시작하기 전에 다음에 대해 장시간 사고를 투입합니다:

**사양과 진화:**
- 사양의 더 깊은 함의
- 반복에 걸친 의미 있는 진행을 만드는 방법
- 각 반복을 가치 있고 유일하게 만드는 요소
- 일관성과 혁신의 균형

**병렬 전략:**
- 요청된 횟수에 맞는 최적 하위 에이전트 분배
- 다양성을 극대화하기 위해 서로 다른 창의 방향을 할당하는 방법
- 무한 모드에서의 물결 크기와 타이밍
- 여러 병렬 에이전트에 걸친 컨텍스트 관리

**조율 과제:**
- 병렬 스트림 간 중복 개념을 막는 방법
- 각 에이전트가 진짜 유일한 산출을 내도록 하는 전략
- 동시 쓰기 시 파일 이름과 디렉터리 구성 관리
- 병렬 출력에 대한 품질 관리 메커니즘

**무한 모드 최적화:**
- 지속적 산출을 위한 물결 기반 생성 패턴
- 여러 물결에 걸친 점진적 정교화 전략
- 컨텍스트 용량 모니터링과 정상적 종료 계획
- 병렬 생성 속도와 혁신의 깊이의 균형

**리스크 완화:**
- 에이전트 실패와 반복 재할당 처리
- 병렬 실행에도 전체 진행이 일관되게 유지되도록 함
- 전체 시스템에 걸친 컨텍스트 윈도 한계 관리
- 모든 병렬 출력에서 사양 준수 유지
