# Common Spec — Architecture Decision Record (ADR) 포맷

---

## ADR이란

아키텍처 결정 사항을 **왜** 그렇게 결정했는지 기록하는 문서.  
코드는 **무엇**을 하는지 보여주지만, ADR은 **왜** 그 선택을 했는지를 보존한다.

---

## 상태 정의

| 상태 | 의미 |
|------|------|
| `제안됨` | 논의 중 — 아직 결정되지 않음 |
| `수락됨` | 팀 합의 완료 — 현재 유효한 결정 |
| `폐기됨` | 더 이상 적용하지 않음 (대체 없음) |
| `대체됨` | 다른 ADR로 교체됨 — 어떤 ADR인지 명시 |

| 수정 금지 | 수락된 ADR은 수정하지 않음 — 새 ADR로 대체 |

## 작성 가이드

### 배경 작성 팁
- 미래 독자가 당시 상황을 이해할 수 있도록 충분한 컨텍스트 제공
- "당연한" 제약도 명시 (팀 규모, 예산, 기간 등)
- 결정 당시의 기술 성숙도 언급

### 검토한 옵션 작성 팁
- 최소 2개 이상 옵션 기술 (선택지가 없었다면 결정이 아님)
- 선택하지 않은 이유를 명확히

### 결과 작성 팁
- 부정적 결과를 회피하지 않고 솔직하게 기록
- 트레이드오프를 인정하는 것이 좋은 ADR

## 예시 ADR

```markdown
# ADR-0001: LLM 오케스트레이션 라이브러리로 LangChain 선택

## 상태
수락됨

## 날짜
2026-05-03

## 결정자
백엔드 팀

---

## 배경

Ice Breaker 서비스는 여러 LLM 체인과 ReAct 에이전트를 조합해야 한다.
직접 OpenAI API를 호출하면 프롬프트 관리, 파싱, 에이전트 루프를 모두 구현해야 한다.

---

## 검토한 옵션

### 옵션 1 — OpenAI SDK 직접 사용
- 장점: 의존성 최소, 가장 최신 모델 기능 즉시 사용 가능
- 단점: 에이전트 루프, 파서, 프롬프트 관리 직접 구현 필요

### 옵션 2 — LangChain (선택)
- 장점: ReAct 에이전트, 파서, 체인 추상화 제공. 생태계 풍부
- 단점: 빠른 API 변경으로 마이너 버전 간 호환성 주의 필요

### 옵션 3 — LlamaIndex
- 장점: RAG에 특화
- 단점: 에이전트 기능 상대적으로 약함. 팀 경험 없음

---

## 결정

LangChain을 선택한다. 왜냐하면 ReAct 에이전트와 PydanticOutputParser가
우리가 필요한 기능을 즉시 제공하며, 팀이 이미 경험을 보유하고 있기 때문이다.

---

## 결과

### 긍정적 결과
- 에이전트 루프 구현 불필요 — 개발 속도 향상
- LangSmith로 트레이싱 즉시 연동 가능

### 부정적 결과 / 트레이드오프
- LangChain 버전 업그레이드 시 API 변경 주의 필요
- 버전 고정(pip pin) 필수

---

## 관련 문서
- 관련 스펙: `common/agent.md`, `common/versions.md`
```
