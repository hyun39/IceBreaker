# Enterprise Spec — 스펙-코드 초기 동기화 (Bootstrap Guide)

> Living Spec + Executable Spec 시스템을 **처음 구성할 때** 따라야 할 절차.  
> `01.03_std_executable_specification.md` + `07.02_std_living_specification.md` 적용 전 선행 작업.

---

## 두 가지 시작점

```
Greenfield (신규 프로젝트)           Brownfield (기존 코드베이스)
─────────────────────────           ──────────────────────────────
스펙 먼저 → 코드 따름               코드 먼저 → 스펙 역생성
Baseline = Phase 01 스펙 완성        Baseline = 기존 코드 스냅샷
동기화 시작 = 첫 배포 이전           동기화 시작 = 스냅샷 커밋 직후
BDD 작성 = 코드 구현과 동시          BDD 작성 = Happy Path부터 점진적
```

---

## Path A: Greenfield (신규 프로젝트)

**"코드 한 줄 없는 상태에서 시작"**

### Day 0: 스펙 Baseline 확립

```bash
# 1. Golden Path로 레포 생성 (Backstage 템플릿)
gh repo create corp/{service-name} --template corp/golden-path-template

# 2. Phase 01 스펙 작성 (01.01 → 이해관계자 승인)
vim specs/business_spec.md

# 3. API 계약 초안 작성 (구현 전 Design-first)
vim specs/api_contract.md

# 4. 초기 Baseline 커밋 — 이 커밋이 기준점
git add specs/
git commit -m "spec: initial baseline — business_spec v1.0"
git tag spec-baseline-v1.0
```

### Day 1~N: 코드 구현 (스펙을 따름)

```bash
# FastAPI 구현 → OpenAPI 자동 생성 확인
uv run python -c "
from app.main import app
import json
print(json.dumps(app.openapi(), indent=2, ensure_ascii=False))
" | head -50
```

**첫 OpenAPI Baseline 커밋** (코드 완성 직후):

```bash
# OpenAPI 추출 → api_contract.md 갱신
uv run python scripts/openapi_to_markdown.py \
  --input <(uv run python -c "from app.main import app; import json; print(json.dumps(app.openapi()))") \
  --output specs/api_contract.md

git add specs/api_contract.md
git commit -m "spec: sync api_contract.md with initial FastAPI implementation"
git tag api-baseline-v1.0
```

**첫 BDD Feature 파일 작성** — 이후 AC 추가 시마다 feature 업데이트:

```bash
mkdir -p tests/bdd/features tests/bdd/steps

# Happy Path feature 파일 먼저
cat > tests/bdd/features/mart_trend.feature << 'EOF'
# Covers: AC-010, AC-011, AC-012  ← business_spec.md의 AC 번호 참조
Feature: Mart Trend Analysis 조회

  Scenario: 거래일 정상 조회
    Given 거래일 "2026-05-01"의 파이프라인이 완료됐다
    When GET /api/v1/mart/trend-analysis?trade_date=2026-05-01 호출하면
    Then 응답 코드는 200이다
    And 11개 Sector 분석이 포함된다
EOF

# Step 구현
cat > tests/bdd/steps/mart_trend_steps.py << 'EOF'
from pytest_bdd import given, when, then, parsers
# ... step 구현
EOF

# BDD 처음 실행
uv run pytest tests/bdd/ -v
```

**CI 활성화** — 모든 파이프라인 동시 켜기:

```yaml
# .github/workflows/ci.yml 최종 활성화
jobs:
  spec-drift-check:  # ON   ← api_contract.md vs 실제 코드 비교
  bdd-test:          # ON   ← Gherkin 실행
  spec-freshness:    # ON   ← 스펙 갱신 여부 모니터링
  ai-spec-validator: # ON   ← PR 시 완전성 검증
```

### Greenfield 완료 기준

```
✅ specs/business_spec.md — 이해관계자 서명 완료
✅ specs/api_contract.md  — FastAPI 코드와 일치 (Drift 0건)
✅ tests/bdd/features/    — Spec Coverage ≥ 50%
✅ CI: spec-drift-check   — 통과
✅ CI: bdd-test           — 통과
✅ git tag: spec-baseline-v1.0, api-baseline-v1.0
```

## Path B: Brownfield (기존 코드베이스)

**"코드는 있지만 스펙이 없거나 낡은 상태"**

### 단계 1: 현재 코드 상태 스냅샷 (Baseline 확립)

가장 먼저 **현재 상태를 Baseline으로 고정**한다. 이후 모든 변경을 이 Baseline과 비교한다.

```bash
# 1. 현재 OpenAPI 스냅샷 추출 → 파일로 저장 (이것이 Baseline)
uv run python -c "
from app.main import app
import json
json.dump(app.openapi(), open('specs/api_contract_baseline.json', 'w'),
          indent=2, ensure_ascii=False)
print('✅ Baseline 저장 완료')
"

# 2. DB Schema 스냅샷
pg_dump --schema-only $DATABASE_URL > specs/schema_baseline.sql

# 3. Baseline 커밋 — 이 커밋이 기준점
git add specs/
git commit -m "spec: brownfield baseline snapshot $(date +%Y-%m-%d)"
git tag spec-baseline-brownfield-v1
```

> **⚠️ 이 커밋 이후부터 Drift 체크가 시작된다.**  
> Baseline 이전의 불일치는 허용. Baseline 이후의 불일치만 차단.

### 단계 2: AI로 스펙 역생성

```bash
# AI가 기존 코드에서 비즈니스 스펙 초안 생성
uv run python scripts/reverse_spec_from_code.py \
  --router apps/api/app/routers/ \
  --output specs/business_spec_draft.md \
  --model gpt-4o-mini

# 생성된 초안 확인 — [TODO: 확인 필요] 항목 수동 보완
cat specs/business_spec_draft.md
```

```python
# scripts/reverse_spec_from_code.py
import ast, os, glob
from openai import OpenAI

PROMPT = """
다음 FastAPI 라우터 코드를 분석해 비즈니스 스펙을 역생성하라.

코드:
{code}

생성 형식 (01.01_gov_business_requirements.md 형식):
- 배경 및 목적
- 유저스토리 (As a... I want to... So that...)
- 인수기준 (Gherkin Given/When/Then)
- 비기능 요건 추정

⚠️ 코드에서 알 수 없는 부분은 [TODO: 확인 필요]로 표시
⚠️ 구현 방법이 아닌 비즈니스 관점으로 작성
"""

def reverse_spec(router_dir: str) -> str:
    code_snippets = []
    for f in glob.glob(f"{router_dir}/**/*.py", recursive=True):
        code_snippets.append(open(f).read())

    client = OpenAI()
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        temperature=0.2,
        messages=[{
            "role": "user",
            "content": PROMPT.format(code="\n\n".join(code_snippets[:5]))  # 5개 파일씩
        }]
    )
    return resp.choices[0].message.content
```

### 단계 3: 스펙 초안 검토 및 정제

```
AI 생성 초안 (specs/business_spec_draft.md)
        │
        ▼ 팀 리뷰 (PO + Tech Lead, 1~2일)

```

### 단계 4: BDD Feature 점진적 추가 (우선순위 기반)

**한 번에 다 만들려 하지 않는다.** Critical Path부터 시작해 점진적으로 커버리지를 높인다.

```
Week 1: Happy Path (핵심 기능) → Coverage 30%
Week 2: 주요 에러 케이스      → Coverage 50%
Week 3: 엣지 케이스           → Coverage 70%
Week 4: 전체 AC 커버          → Coverage 80%+
```

```bash
# 우선순위 BDD 작성 순서

# 1순위: 가장 중요한 Happy Path
cat > tests/bdd/features/ods_prices.feature << 'EOF'
# Covers: AC-001 (Happy Path만 먼저)
Feature: ODS 종목 가격 조회
  Scenario: 정상 조회
    Given 거래일 "2026-05-01" 데이터가 존재한다
    When GET /api/v1/ods/prices?trade_date=2026-05-01 호출하면
    Then 응답 코드는 200이다
EOF

# CI에서 실행해 통과 확인 후 다음 시나리오 추가
uv run pytest tests/bdd/ --tb=short

# 2순위: 에러 케이스
cat >> tests/bdd/features/ods_prices.feature << 'EOF'

  Scenario: 비거래일 조회
    Given "2026-05-03"은 비거래일이다
    When GET /api/v1/ods/prices?trade_date=2026-05-03 호출하면
    Then 응답 코드는 404이다
EOF
```

### 단계 5: CI 점진적 활성화

**한 번에 모든 CI를 켜면 수백 개 오류가 쏟아진다.** 단계적으로 활성화한다.

```yaml
# Week 1: Baseline 스냅샷 비교만 활성화
spec-drift-check:
  enabled: true
  mode: warn-only   # ← 실패해도 PR 차단하지 않음 (경고만)

# Week 2: BDD 추가 후 활성화
bdd-test:
  enabled: true
  coverage-threshold: 30%   # ← 낮은 임계치로 시작

# Week 3: 임계치 상향
bdd-test:
  coverage-threshold: 50%

# Week 4: 완전 활성화 (PR 차단)
spec-drift-check:
  mode: block         # ← 이제 Drift 발생 시 PR 차단
bdd-test:
  coverage-threshold: 80%
ai-spec-validator:
  enabled: true
```

## 흔한 초기 오류와 해결

| 오류 | 원인 | 해결 |
|------|------|------|
| Drift 체크 즉시 실패 (수백 건) | Baseline 없이 block 모드 켬 | Baseline 커밋 후 warn-only로 시작 |
| BDD step 매칭 실패 | feature 파일과 step 파일 불일치 | `pytest --collect-only`로 매칭 확인 |
| OpenAPI 자동 생성 오류 | 앱 임포트 에러 | `uv run python -c "from app.main import app"` 단독 실행 확인 |
| 역생성 스펙 품질 낮음 | 코드 구조 복잡 | 라우터 파일 단위로 분할 생성 |
| Coverage 임계치 미달 | BDD 작성 속도 느림 | Happy Path만 우선, threshold 낮게 시작 |
