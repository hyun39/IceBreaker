# Enterprise Spec — 살아있는 스펙 (Living Specification)

> **핵심**: 스펙이 항상 코드의 현재 상태를 반영한다.  
> 코드가 바뀌면 스펙도 자동으로 갱신되거나, 불일치가 CI에서 즉시 감지된다.  
> `07.01_gov_sre_practices.md`의 SLO와 연계해 운영 지표가 스펙 진화를 트리거한다.

---

## Living Spec의 세 가지 메커니즘

```
[메커니즘 1] Code → Spec 역동기화
  코드에서 스펙 자동 추출 (OpenAPI, ERD, 아키텍처 다이어그램)
        │
[메커니즘 2] Spec Drift 감지
  스펙과 코드가 불일치할 때 CI에서 즉시 감지·차단
        │
[메커니즘 3] 운영 지표 → 스펙 갱신 트리거
  SLO 미달, UX 지표 저하 → 스펙 재검토 이슈 자동 생성
```

---

## 메커니즘 1: Code → Spec 역동기화

### 1-1. OpenAPI Code-first (FastAPI → 스펙 자동 갱신)

FastAPI는 코드에서 OpenAPI를 자동 생성한다. 이를 CI에서 `api_contract.md`와 동기화한다.

```yaml
# .github/workflows/spec-sync.yml
name: Sync OpenAPI to Spec

on:
  push:
    branches: [main]
    paths: ["apps/api/**"]

jobs:
  sync-openapi:
    steps:
      - name: Generate OpenAPI from FastAPI
        run: |
          uv run python -c "
          from app.main import app
          import json
          spec = app.openapi()
          json.dump(spec, open('openapi.json', 'w'), indent=2, ensure_ascii=False)
          "

      - name: Convert OpenAPI → api_contract.md
        run: |
          uv run python scripts/openapi_to_markdown.py \
            --input openapi.json \
            --output specs/api_contract.md

      - name: Create PR if changed
        uses: peter-evans/create-pull-request@v6
        with:
          title: "docs: sync api_contract.md from FastAPI schema"
          body: |
            FastAPI 코드가 변경되어 api_contract.md를 자동 갱신합니다.
            
            > ⚠️ 스펙 변경이 의도된 것인지 확인 후 머지하세요.
          branch: spec-sync/api-contract
          labels: ["spec-sync", "automated"]
```

```python
# scripts/openapi_to_markdown.py
import json, sys

def convert(openapi: dict) -> str:
    lines = ["# API Contract (Auto-generated)\n"]
    lines.append(f"> 자동 생성 — 수동 편집 금지. 코드 변경 → PR 자동 생성\n\n")

    for path, methods in openapi["paths"].items():
        for method, spec in methods.items():
            lines.append(f"## `{method.upper()} {path}`\n")
            lines.append(f"{spec.get('summary', '')}\n\n")

            # 요청 파라미터
            params = spec.get("parameters", [])
            if params:
                lines.append("### 요청 파라미터\n\n")
                lines.append("| 이름 | 타입 | 필수 | 설명 |\n|------|------|------|------|\n")
                for p in params:
                    required = "✅" if p.get("required") else "—"
                    lines.append(f"| `{p['name']}` | {p['schema'].get('type','')} | {required} | {p.get('description','')} |\n")

            # 응답 코드
            lines.append("\n### 응답\n\n")
            lines.append("| 코드 | 설명 |\n|------|------|\n")
            for code, resp in spec.get("responses", {}).items():
                lines.append(f"| {code} | {resp.get('description','')} |\n")
            lines.append("\n---\n\n")

    return "".join(lines)
```

## 메커니즘 2: Spec Drift 감지

### 2-1. OpenAPI Drift 체크

코드에서 생성한 OpenAPI와 스펙의 `api_contract.md`가 다르면 CI 실패.

```yaml
# .github/workflows/ci.yml에 추가

  spec-drift-check:
    runs-on: ubuntu-latest
    steps:
      - name: Generate current OpenAPI
        run: uv run python scripts/gen_openapi.py > /tmp/current_openapi.json

      - name: Compare with committed spec
        run: |
          # oasdiff로 변경 감지
          docker run --rm \
            -v /tmp/current_openapi.json:/current.json \
            -v specs/api_contract.json:/committed.json \
            tufin/oasdiff diff /committed.json /current.json \
            --fail-on ERR
          # Breaking Change 있으면 CI 실패
```

### 2-3. Spec Freshness 체크

마지막 스펙 갱신 후 코드 커밋이 N건 이상이면 경고.

```python
# scripts/spec_freshness_check.py
import subprocess, sys
from pathlib import Path

def check_freshness(spec_file: str, threshold_commits: int = 20):
    # 스펙 파일의 마지막 커밋 해시
    spec_last = subprocess.check_output(
        ["git", "log", "-1", "--format=%H", spec_file]
    ).decode().strip()

    # 그 이후 코드 커밋 수 (apps/ 디렉토리)
    commits_since = subprocess.check_output(
        ["git", "rev-list", "--count", f"{spec_last}..HEAD", "--", "apps/"]
    ).decode().strip()

    count = int(commits_since)
    if count > threshold_commits:
        print(f"⚠️  SPEC STALE: {spec_file}")
        print(f"   마지막 갱신 후 코드 커밋 {count}건 (임계치: {threshold_commits})")
        print(f"   스펙 검토 또는 갱신이 필요합니다.")
        sys.exit(1)

check_freshness("specs/business_spec.md")
check_freshness("specs/api_contract.md")
```

## 메커니즘 3: 운영 지표 → 스펙 갱신 트리거

### 3-1. SLO 미달 → 스펙 재검토 이슈 자동 생성

```python
# scripts/slo_to_spec_trigger.py — Prometheus AlertManager webhook
from fastapi import FastAPI, Request
import httpx, os

app = FastAPI()

JIRA_URL = os.environ["JIRA_URL"]
JIRA_TOKEN = os.environ["JIRA_TOKEN"]
SPEC_REVIEW_LABEL = "spec-review-required"

@app.post("/webhook/slo-alert")
async def handle_slo_alert(request: Request):
    alert = await request.json()

    for alert_item in alert.get("alerts", []):
        if alert_item["status"] == "firing":
            service = alert_item["labels"].get("service", "unknown")
            slo_name = alert_item["labels"].get("slo", "unknown")
            error_budget_remaining = alert_item["labels"].get("budget_remaining", "unknown")

            # Jira 이슈 자동 생성
            await create_spec_review_issue(
                service=service,
                slo_name=slo_name,
                budget_remaining=error_budget_remaining,
                alert_details=alert_item,
            )

async def create_spec_review_issue(service, slo_name, budget_remaining, alert_details):
    issue_body = f"""
## SLO 미달로 인한 스펙 재검토 요청

| 항목 | 값 |
|------|-----|
| 서비스 | `{service}` |
| SLO | `{slo_name}` |
| Error Budget 잔여 | `{budget_remaining}%` |

### 재검토 항목
- [ ] 현재 SLO 목표값이 적절한가? (`07.01_gov_sre_practices.md` 참조)
- [ ] 기술적 부채가 비기능 요건에 반영됐는가?
- [ ] 알림 임계치 조정이 필요한가?
- [ ] 아키텍처 변경이 필요한가? (ADR 작성 필요 시 `02.01_gov_adr_format.md` 참조)

### 관련 스펙
- `specs/business_spec.md` — 비기능 요건 섹션 재검토
- `07.01_gov_sre_practices.md` — SLO 재정의 절차
    """
    async with httpx.AsyncClient() as client:
        await client.post(
            f"{JIRA_URL}/rest/api/3/issue",
            headers={"Authorization": f"Bearer {JIRA_TOKEN}"},
            json={
                "fields": {
                    "project": {"key": "SPEC"},
                    "summary": f"[SLO 미달] {service} — 스펙 재검토 필요",
                    "description": {"type": "doc", "content": [{"type": "paragraph", "content": [{"type": "text", "text": issue_body}]}]},
                    "issuetype": {"name": "Task"},
                    "labels": [SPEC_REVIEW_LABEL, service],
                    "priority": {"name": "High"},
                }
            }
        )
```

```yaml
# Prometheus AlertManager 설정 — SLO 미달 시 webhook 호출
receivers:
  - name: spec-review-trigger
    webhook_configs:
      - url: "https://spec-sync.internal/webhook/slo-alert"
        send_resolved: false

route:
  routes:
    - match:
        alertname: ErrorBudgetBurnRateFast
      receiver: spec-review-trigger
      group_wait: 0s
```

### 3-2. UX 지표 저하 → 스펙 재검토

```python
# scripts/ux_metrics_check.py — PostHog 데이터 → 스펙 갱신 트리거
# 주간 배치로 실행 (GitHub Actions cron)

import httpx, os

POSTHOG_URL = os.environ["POSTHOG_URL"]
POSTHOG_TOKEN = os.environ["POSTHOG_TOKEN"]

UX_THRESHOLDS = {
    "task_success_rate": 0.90,   # 90% 미만이면 스펙 재검토
    "session_duration_p50": 120, # 중앙값 2분 이하면 재검토
    "error_rate": 0.05,          # 5% 초과 시 재검토
}

async def check_ux_metrics_and_trigger():
    # PostHog API에서 지표 조회
    metrics = await fetch_ux_metrics()

    violations = []
    for metric, threshold in UX_THRESHOLDS.items():
        value = metrics.get(metric, 0)
        if metric == "task_success_rate" and value < threshold:
            violations.append(f"Task Success Rate {value:.1%} < {threshold:.1%}")
        elif metric == "error_rate" and value > threshold:
            violations.append(f"Error Rate {value:.1%} > {threshold:.1%}")

    if violations:
        await create_spec_review_issue_ux(violations)
```

## Living Spec 체크리스트 (PR 자동 확인)

```yaml
# .github/workflows/living-spec-check.yml
on:
  pull_request:
    paths: ["apps/**", "specs/**"]

jobs:
  living-spec:
    steps:
      - name: OpenAPI Drift Check
        run: python scripts/spec_drift_check.py --type openapi

      - name: Spec Freshness Check
        run: python scripts/spec_freshness_check.py

      - name: Pact Can-I-Deploy
        run: pact-broker can-i-deploy ...

      - name: Comment on PR
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              body: `## 📋 Living Spec 상태
              | 체크 | 결과 |
              |------|------|
              | OpenAPI 드리프트 | ${{ steps.openapi.outcome == 'success' && '✅ 없음' || '❌ 발생' }} |
              | 스펙 신선도 | ${{ steps.freshness.outcome == 'success' && '✅ 최신' || '⚠️ 갱신 필요' }} |
              | Pact 계약 | ${{ steps.pact.outcome == 'success' && '✅ 만족' || '❌ 위반' }} |`
            });
```
