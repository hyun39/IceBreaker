# Enterprise Spec — 자율 스펙 진화 (Autonomous Specification) — Level 5

> **핵심**: AI가 스펙을 발견·검증·갱신·진화시키는 자율 루프를 구성한다.  
> 사람은 AI의 제안을 승인하거나 거부하는 역할만 한다.  
> Level 4(`01.03`, `07.02`)의 자동화 기반 위에서 동작한다.

---

## Level 5의 세 가지 AI 역할

```
AI Validator  → 스펙 완전성·일관성을 자동으로 검증
AI Generator  → 코드·이슈·지표에서 스펙 초안을 자동으로 생성
AI Evolutor   → 프로덕션 데이터로 스펙 개선안을 지속적으로 제안
```

---

## AI Spec Validator

PR이 열릴 때 스펙 완전성·일관성을 LLM이 자동 검증한다.

### 검증 항목

| 검증 | 내용 |
|------|------|
| 완전성 | 에러 상태가 모두 AC로 정의됐는가? |
| 일관성 | API 계약과 비즈니스 스펙의 응답 필드가 일치하는가? |
| 추적성 | 모든 FR이 최소 1개 이상의 AC를 갖는가? |
| 면책문구 | 금융 도메인 기능에 면책문구가 포함됐는가? |
| 접근성 | UX 스펙에 에러/빈/로딩 상태가 정의됐는가? |

### GitHub Actions 구현

```yaml
# .github/workflows/ai-spec-validator.yml
name: AI Spec Validator

on:
  pull_request:
    paths: ["specs/**/*.md"]
    types: [opened, synchronize]

jobs:
  validate-spec:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - uses: astral-sh/setup-uv@v3

      - name: Run AI Spec Validator
        id: validator
        run: |
          uv run python scripts/ai_spec_validator.py \
            --changed-files "$(git diff --name-only origin/main HEAD -- specs/)" \
            --output /tmp/validation_result.json
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}

      - name: Post Validation Result to PR
        uses: actions/github-script@v7
        with:
          script: |
            const result = require('/tmp/validation_result.json');
            const icon = result.passed ? '✅' : '⚠️';

            let body = `## ${icon} AI Spec Validator 결과\n\n`;
            body += `| 검증 항목 | 결과 | 상세 |\n|----------|------|------|\n`;
            for (const check of result.checks) {
              const status = check.passed ? '✅' : '❌';
              body += `| ${check.name} | ${status} | ${check.detail} |\n`;
            }

            if (!result.passed) {
              body += `\n### 🔧 AI 제안 수정사항\n\n`;
              for (const suggestion of result.suggestions) {
                body += `- **${suggestion.file}**: ${suggestion.action}\n`;
                if (suggestion.draft) body += `\`\`\`markdown\n${suggestion.draft}\n\`\`\`\n`;
              }
            }

            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body,
            });
```

### 검증 스크립트

```python
# scripts/ai_spec_validator.py
import json, sys
from openai import OpenAI
from pathlib import Path

VALIDATOR_SYSTEM = """
당신은 Spec-Driven Development 전문가입니다.
비즈니스 스펙 문서를 분석해 완전성·일관성·추적성을 검증합니다.

검증 규칙:
1. 모든 기능 요건(FR)은 최소 1개의 인수기준(AC)을 가져야 한다
2. 에러 상태(비거래일, 데이터 없음, 분석 미완료)가 AC로 정의되어야 한다
3. 금융 도메인 기능(investment, analysis, portfolio)은 면책문구 AC가 있어야 한다
4. API가 언급된 경우 성공(2xx), 에러(4xx), 서버오류(5xx) 응답 AC가 있어야 한다
5. UX 관련 요건은 로딩·빈 상태·에러 상태 AC가 있어야 한다

출력 형식: JSON
"""

VALIDATOR_PROMPT = """
다음 스펙 문서를 검증하라:

{spec_content}

결과를 JSON으로 반환:
{{
  "passed": true/false,
  "checks": [
    {{"name": "완전성", "passed": true/false, "detail": "설명"}},
    {{"name": "에러 상태", "passed": true/false, "detail": "설명"}},
    {{"name": "면책문구", "passed": true/false, "detail": "설명"}},
    {{"name": "AC 추적성", "passed": true/false, "detail": "설명"}}
  ],
  "suggestions": [
    {{
      "file": "파일명",
      "action": "무엇을 추가/수정해야 하는가",
      "draft": "추가할 내용 초안 (Markdown)"
    }}
  ]
}}
"""

def validate_spec(spec_file: str) -> dict:
    content = Path(spec_file).read_text()
    client = OpenAI()
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        temperature=0,
        response_format={"type": "json_object"},
        messages=[
            {"role": "system", "content": VALIDATOR_SYSTEM},
            {"role": "user", "content": VALIDATOR_PROMPT.format(spec_content=content)},
        ],
    )
    return json.loads(response.choices[0].message.content)
```

        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

          git checkout -b $BRANCH
          cp /tmp/spec_draft.md specs/business_spec_draft.md
          git add . && git commit -m "feat(spec): AI-generated spec draft for #${{ github.event.issue.number }}"
          gh pr create \
            --title "📋 [AI Draft] Spec for #${{ github.event.issue.number }}" \
            --body "이슈 #${{ github.event.issue.number }}에서 AI가 생성한 스펙 초안입니다. 검토 후 수정하세요." \
            --label "ai-generated,needs-review"

## AI Evolutor — 지속적 스펙 진화

프로덕션 데이터·사용자 행동·SLO 지표를 분석해 스펙 개선안을 주기적으로 제안한다.

### 주간 자동 스펙 진화 리포트

```yaml
# .github/workflows/ai-spec-evolution.yml
on:
  schedule:
    - cron: "0 9 * * MON"  # 매주 월요일 09:00 UTC

jobs:
  spec-evolution:
    steps:
      - name: Collect Signals
        run: |
          uv run python scripts/collect_evolution_signals.py \
            --output /tmp/signals.json
        env:
          PROMETHEUS_URL: ${{ secrets.PROMETHEUS_URL }}
          POSTHOG_TOKEN: ${{ secrets.POSTHOG_TOKEN }}
          PAGERDUTY_TOKEN: ${{ secrets.PAGERDUTY_TOKEN }}

      - name: AI Evolution Analysis
        run: |
          uv run python scripts/ai_spec_evolutor.py \
            --signals /tmp/signals.json \
            --current-specs specs/ \
            --output /tmp/evolution_report.md
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}

      - name: Create Evolution Issue
        uses: actions/github-script@v7
        with:
          script: |
            const report = require('fs').readFileSync('/tmp/evolution_report.md', 'utf8');
            github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `🤖 [AI] 주간 스펙 진화 제안 (${new Date().toISOString().slice(0,10)})`,
              body: report,
              labels: ['ai-evolution', 'spec-review'],
            });
```

```python
# scripts/collect_evolution_signals.py
"""
스펙 진화를 위한 신호 수집:
- SLO 달성률 (Prometheus)
- 사용자 행동 패턴 (PostHog)
- Incident 패턴 (PagerDuty)
- Feature Flag 사용률 (OpenFeature)
- BDD 테스트 실패 패턴 (GitHub Actions)
"""

async def collect_signals() -> dict:
    return {
        "slo_breaches": await fetch_slo_breaches(last_days=7),
        "top_errors": await fetch_top_errors(last_days=7),
        "unused_features": await fetch_low_usage_features(threshold=0.05),
        "user_drop_off": await fetch_user_drop_off_points(),
        "frequent_support": await fetch_frequent_support_topics(),
        "bdd_failures": await fetch_bdd_failure_patterns(),
    }
```

## Human-in-the-Loop (승인 게이트)

Level 5에서도 **사람의 최종 승인**은 유지한다.

```
AI 제안 생성
    │
    ▼ GitHub Issue 또는 PR
사람 검토 (PO + Tech Lead)
    │
    ├─ Approve → 스펙 PR 머지
    ├─ Request Changes → AI 재분석
    └─ Dismiss → 이번 주기 스킵 + 사유 기록
```

### 자동화 vs 수동 기준

| 액션 | 자동 | 수동 필요 |
|------|------|---------|
| 스펙 완전성 경고 | ✅ | — |
| 스펙 초안 생성 | ✅ | 최종 확인 |
| SLO → 이슈 생성 | ✅ | 우선순위 결정 |
| 스펙 진화 제안 | ✅ | 채택 여부 결정 |
| **스펙 PR 머지** | ❌ | **반드시 사람** |
| **요건 삭제** | ❌ | **반드시 사람** |
| **비용·법적 영향** | ❌ | **반드시 사람** |

## 전체 Autonomous Spec 루프

```
[프로덕션]
  SLO 지표, 사용자 행동, 에러 패턴
        │ (주간 수집)
        ▼
[AI Evolutor]
  신호 분석 → 스펙 개선 제안 → GitHub Issue
        │ (PO 승인)
        ▼
[AI Generator]
  승인된 제안 → 스펙 초안 생성 → PR
        │ (Tech Lead 리뷰)
        ▼
[AI Validator]
  스펙 PR → 완전성·일관성 검증 → PR 댓글
        │ (자동 체크 통과 + 사람 승인)
        ▼
[스펙 머지]
  → prototype.yml 트리거
  → L1/L2 React 목업 자동 생성 (01.02 참조)
  → 이해관계자 리뷰
        │
        ▼
[개발 착수]
  → BDD feature 파일 작성 (01.03 참조)
  → 코드 구현
  → OpenAPI 역동기화 (07.02 참조)
        │
        ▼
[프로덕션 배포]
  → 다시 신호 수집 루프
```
