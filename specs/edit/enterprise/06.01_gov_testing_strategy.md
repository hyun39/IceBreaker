## 계약 테스트 (Consumer-Driven Contract Testing)

### 목적

마이크로서비스 간 API 계약을 **코드로 검증**해 "Producer를 배포했더니 Consumer가 깨지는" 상황을 사전 방지한다.

### 도구: Pact

```
[Consumer 서비스]
  1. 테스트 코드에서 "나는 이런 요청·응답을 기대한다" Pact 파일 생성
  2. Pact 파일을 Pact Broker에 발행

[Producer 서비스]
  3. Pact Broker에서 Consumer의 Pact 파일을 내려받아 검증
  4. 검증 결과를 Pact Broker에 보고

[Pact Broker]
  ├─ Can I Deploy? — 특정 버전이 안전하게 배포 가능한지 확인
  └─ 계약 버전 이력·통지
```

**Consumer 쪽 (FastAPI 소비자)**:

```python
# tests/contract/test_sp500_api_consumer.py
from pact import Consumer, Provider, Like, EachLike, Term
import pytest

@pytest.fixture
def pact():
    return Consumer("frontend-app").has_pact_with(
        Provider("sp500-api"),
        pact_dir="./pacts",
        publish_to_broker=os.getenv("CI") == "true",
        broker_url="https://pact-broker.internal",
    )

def test_get_dw_sector_returns_sector_list(pact):
    expected = {
        "trade_date": Term(r"\d{4}-\d{2}-\d{2}", "2026-05-01"),
        "sectors": EachLike({
            "sector_name": Like("Information Technology"),
            "sector_code": Like("IT"),
            "sector_return_pct": Like(1.23),
            "advance_count": Like(51),
        }),
    }
    (pact
        .given("거래일 2026-05-01 DW 데이터가 존재한다")
        .upon_receiving("DW Sector 집계 요청")
        .with_request("GET", "/api/v1/dw/sector", query={"trade_date": "2026-05-01"})
        .will_respond_with(200, body=expected))

    with pact:
        result = requests.get(f"{pact.uri}/api/v1/dw/sector?trade_date=2026-05-01")
        assert result.status_code == 200
```

**Producer 쪽 (sp500-api 검증)**:

```python
# tests/contract/test_sp500_api_provider.py
from pact import Verifier

def test_provider_contracts():
    verifier = Verifier(
        provider="sp500-api",
        provider_base_url="http://localhost:8000",
    )
    output, _ = verifier.verify_with_broker(
        broker_url="https://pact-broker.internal",
        provider_states_setup_url="http://localhost:8000/_pact/provider-states",
        publish_verification_results=True,
        provider_version=os.getenv("GIT_SHA"),
    )
    assert output == 0
```

**CI 배포 게이트**:

```bash
# 배포 전 "Can I Deploy?" 체크

  --pacticipant sp500-api \
  --version ${GIT_SHA} \
  --to-environment production \
  --broker-base-url https://pact-broker.internal
```

## 보안 테스트 (Security Testing)

### 테스트 유형별 적용

| 유형 | 도구 | 실행 주기 | 차단 기준 |
|------|------|---------|---------|
| SAST (정적 분석) | Semgrep + Bandit(Python) / SpotBugs(Java) | PR마다 | HIGH 이상 |
| SCA (의존성 취약점) | `uv` pip-audit / OWASP Dependency Check | PR마다 | CRITICAL |
| Container Scan | Trivy | 이미지 빌드마다 | CRITICAL |
| DAST (동적 분석) | OWASP ZAP | 주 1회 (staging) | MEDIUM 이상 |
| Secret Scan | TruffleHog / Gitleaks | PR마다 (pre-commit) | 즉시 차단 |
| Penetration Test | 외부 업체 | 연 1회 | 별도 기준 |

### DAST 자동화 (ZAP)

```yaml
# .github/workflows/dast.yml
jobs:
  zap-scan:
    runs-on: ubuntu-latest
    steps:
      - name: ZAP DAST Scan
        uses: zaproxy/action-api-scan@v0.7.0
        with:
          target: "https://api-staging.internal"
          format: openapi
          rules_file_name: ".zap/rules.tsv"
          fail_action: true
          cmd_options: "-z '-config globalexcludeurl.url_list.url.0.regex=.*/healthz'"
```

### Secret 스캔 (Pre-commit + CI)

```yaml

```

## AI 평가 파이프라인 (AI Evaluation Pipeline)

Prompt 변경·모델 변경 시 자동으로 품질 기준을 검증한다.  
→ `enterprise/llmops_07.md` Evaluation 섹션과 연계.

```yaml
# .github/workflows/ai-eval.yml
on:
  pull_request:
    paths:
      - "prompts/**"
      - "app/agent/**"

jobs:
  evaluate:
    steps:
      - name: Run ragas Evaluation
        run: |
          uv run python eval/run_evaluation.py \
            --dataset s3://eval-datasets/golden.jsonl \
            --prompt-version ${{ github.sha }} \
            --fail-on faithfulness:0.85 \
            --fail-on relevancy:0.80 \
            --fail-on sentiment_accuracy:0.90

      - name: Post results to PR
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              body: `## AI Evaluation Results\n${process.env.EVAL_RESULTS}`
            })
```

## 임시 환경 (Ephemeral Preview Environment)

PR마다 독립된 프리뷰 환경을 자동 생성·삭제한다.

```
PR 오픈
  │
  ▼
GitHub Actions
  └─ ArgoCD ApplicationSet 생성
       └─ Namespace: preview-pr-{PR_NUMBER}
           ├─ API 서버: api-pr-123.preview.internal
           └─ 데이터베이스: 스냅샷 기반 (읽기 전용)
  │
  ▼
PR 댓글: "🚀 Preview: https://api-pr-123.preview.internal"
  │
  ▼
PR 닫힘 → Namespace 자동 삭제
```

```yaml
# ArgoCD ApplicationSet — PR 임시 환경 자동 생성
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: preview-apps
spec:
  generators:
    - pullRequest:
        github:
          owner: org
          repo: sp500-platform
          tokenRef: { secretName: github-token, key: token }
        requeueAfterSeconds: 60
  template:
    metadata:
      name: "preview-{{number}}"
    spec:
      destination:
        namespace: "preview-pr-{{number}}"
      source:
        helm:
          values: |
            image.tag: "pr-{{number}}"
            env: preview
            replicaCount: 1
      syncPolicy:
        automated: { prune: true }
```
