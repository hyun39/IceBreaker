여러 팀이 반복 구현하는 공통 패턴을 **내부 패키지**로 제공한다.

```python
from corp_platform_sdk.llm import LLMGatewayClient

# 사용 예시 — FastAPI 앱 초기화
from corp_platform_sdk.fastapi import create_app

app = create_app(
    service_name="sp500-api",
    team="data-platform",
    version="1.0.0",
    # OTel, 보안 헤더, 헬스체크, 에러 핸들러 자동 등록
)
```

## 크로스서비스 통신 표준

| 상황 | 방법 | 근거 |
|------|------|------|
| 동기 요청·응답 (단순 조회) | REST (OpenAPI 3.1) | 범용, 도구 풍부 |
| 고성능 내부 서비스 간 | gRPC (proto3) | 스키마 강제, 효율 |
| 비동기 이벤트 (순서 불필요) | Kafka (이벤트 스키마 레지스트리) | 결합 최소화 |
| 비동기 작업 (순서 보장) | Kafka + 파티션 키 | 도메인 집약 |
| 장시간 작업 결과 전달 | Kafka + 폴링 또는 WebSocket | LLM 등 |

### 통신 방향 원칙

```
[서비스 간 의존성 방향]
  도메인 A → 도메인 B: REST (동기) 또는 Kafka (비동기)

  금지:
  - 순환 의존 (A→B→A)
  - DB 직접 공유 (각 서비스는 자체 DB 소유)
  - 내부 구현 직접 호출 (API·이벤트로만 통신)
```

### Python 빌드 표준

#### 패키지 관리 — `uv` (ADOPT)

`pip`, `pip-tools`, `pipenv`, `poetry`를 **단일 도구 `uv`로 통합**한다.  
Rust 기반으로 pip 대비 **10~100배 빠른** 설치 속도를 제공한다.

```bash
# 설치
curl -LsSf https://astral.sh/uv/install.sh | sh

# 프로젝트 초기화 (pyproject.toml 생성)
uv init sp500-api

# 의존성 설치 (uv.lock 자동 생성 — lockfile 필수)
uv add fastapi pydantic
uv add --dev pytest ruff mypy

# 가상환경 없이 바로 실행
uv run python main.py
uv run pytest

# 프로덕션 설치 (lockfile 기반, 재현 보장)
uv sync --frozen
```

**`pyproject.toml` 표준 구조**

```toml
[project]
name = "sp500-api"
version = "1.0.0"
requires-python = ">=3.12"
dependencies = [
    "fastapi>=0.115",
    "pydantic>=2.7",
    "sqlalchemy[asyncio]>=2.0",
    "opentelemetry-sdk>=1.25",
]

[project.optional-dependencies]
dev = ["pytest>=8", "ruff>=0.4", "mypy>=1.10"]

[tool.uv]
dev-dependencies = ["pytest-asyncio", "testcontainers"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

#### 린팅·포매팅 — `ruff` (ADOPT)

`black` + `isort` + `flake8` + `pylint`을 **`ruff` 단일 도구로 대체**한다.  
Rust 기반으로 기존 도구 대비 **10~100배 빠름**.

```toml
# pyproject.toml
[tool.ruff]
target-version = "py312"
line-length = 100
src = ["app", "tests"]

[tool.ruff.lint]
select = [
    "E",   # pycodestyle errors
    "W",   # pycodestyle warnings
    "F",   # pyflakes
    "I",   # isort
    "B",   # bugbear
    "S",   # bandit (보안)
    "UP",  # pyupgrade
    "ANN", # 타입 어노테이션 강제
]
ignore = ["ANN101", "ANN102"]

[tool.ruff.format]
quote-style = "double"

[tool.mypy]
python_version = "3.12"
strict = true
```

```bash
# CI에서 실행
uv run ruff check .          # 린팅
uv run ruff format --check . # 포매팅 검사
uv run mypy app/             # 타입 체크 (strict)
```

#### Python CI 파이프라인 표준

```yaml
# .github/workflows/ci-python.yml
- name: Set up uv
  uses: astral-sh/setup-uv@v3
  with:
    enable-cache: true           # uv 캐시 자동 (GitHub Actions)

- name: Install dependencies
  run: uv sync --frozen          # lockfile 기반 재현 설치

- name: Lint & Format
  run: |
    uv run ruff check .
    uv run ruff format --check .
    uv run mypy app/

- name: Test
  run: uv run pytest --cov=app --cov-fail-under=80
```

### Java 빌드 표준

#### 빌드 도구 — Gradle 8 + Kotlin DSL (ADOPT)

신규 프로젝트는 **Gradle 8 + Kotlin DSL(`build.gradle.kts`)을 표준**으로 한다.  
Maven은 기존 프로젝트 유지보수만 허용.

```kotlin
// build.gradle.kts
plugins {
    java
    id("org.springframework.boot") version "3.3.0"
    id("io.spring.dependency-management") version "1.1.5"
    id("com.diffplug.spotless") version "6.25.0"   // 코드 포매터
}

java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web")
    implementation("org.springframework.boot:spring-boot-starter-actuator")
    testImplementation("org.springframework.boot:spring-boot-starter-test")
}

// Spotless — 포매팅 표준화 (Google Java Format)
spotless {
    java {
        googleJavaFormat("1.22.0")
        removeUnusedImports()
        trimTrailingWhitespace()
    }
}

// 빌드 캐시 활성화 (CI 속도 향상)
buildCache {
    local { isEnabled = true }
    remote<HttpBuildCache> {
        url = uri("https://build-cache.internal/cache/")
        isPush = System.getenv("CI") == "true"
    }
}
```

#### GraalVM Native Image (ASSESS)

시작 시간이 중요한 서비스(Lambda·사이드카·CLI)에 한해 검토한다.

```kotlin
// build.gradle.kts — Native Image 빌드
plugins {
    id("org.graalvm.buildtools.native") version "0.10.2"
}

graalvmNative {
    binaries.named("main") {
        imageName = "sp500-api"
        buildArgs(
            "--no-fallback",
            "--initialize-at-build-time=org.slf4j",
            "-H:+ReportExceptionStackTraces",
        )
    }
}
```

| 항목 | JVM | GraalVM Native |
|------|-----|--------------|
| 시작 시간 | 2~5초 | 50~200ms |
| 메모리 | 256~512MB | 50~100MB |
| 처리량 | 높음 | JVM보다 낮음 |
| 빌드 시간 | 30초 | 3~10분 |
| 적합 | 장기 실행 API | CLI·Lambda·사이드카 |

#### 모노레포 — Turborepo (ADOPT)

여러 팀이 공유하는 Design System·공용 패키지는 **Turborepo 모노레포**로 관리한다.

```json
// turbo.json
{
  "$schema": "https://turbo.build/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],   // 의존 패키지 먼저 빌드
      "outputs": ["dist/**", ".next/**"]
    },
    "lint": { "outputs": [] },
    "test": {
      "dependsOn": ["build"],
      "inputs": ["src/**", "tests/**"]
    },
    "dev": { "cache": false, "persistent": true }
  },
  "remoteCache": {
    "enabled": true,
    "apiUrl": "https://build-cache.internal"  // 원격 캐시
  }
}
```

```

├── @corp/design-system/   ← 공용 UI 컴포넌트
```

### 컨테이너 빌드 표준

#### BuildKit + 캐시 마운트 (ADOPT)

```dockerfile
# Dockerfile — Python (uv + BuildKit 캐시 최적화)
FROM python:3.12-slim AS builder
WORKDIR /app

# BuildKit 캐시 마운트 — uv 캐시 레이어 재사용
RUN --mount=type=cache,target=/root/.cache/uv \
    pip install uv

COPY pyproject.toml uv.lock ./
RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --frozen --no-dev

FROM python:3.12-slim AS runtime
WORKDIR /app
RUN useradd -m -u 1000 appuser
COPY --from=builder /app/.venv /app/.venv
COPY app/ ./app/
USER appuser
ENV PATH="/app/.venv/bin:$PATH"
CMD ["python", "-m", "uvicorn", "app.main:app", "--host", "0.0.0.0"]
```

```dockerfile
# Dockerfile — Java (Gradle + BuildKit + Distroless)
FROM eclipse-temurin:21-jdk-alpine AS builder
WORKDIR /app

# Gradle 캐시 마운트
RUN --mount=type=cache,target=/root/.gradle \
    ./gradlew dependencies --no-daemon

COPY . .
RUN --mount=type=cache,target=/root/.gradle \
    ./gradlew bootJar --no-daemon

# Distroless — 최소 공격 표면 (shell 없음)
FROM gcr.io/distroless/java21-debian12 AS runtime
WORKDIR /app
COPY --from=builder /app/build/libs/*.jar app.jar
USER nonroot
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```dockerfile
# Dockerfile — Frontend (Vite + nginx)
FROM node:20-alpine AS builder
WORKDIR /app
RUN corepack enable pnpm

# pnpm 캐시 최적화
COPY package.json pnpm-lock.yaml ./
RUN --mount=type=cache,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile

COPY . .
RUN pnpm build

FROM nginx:1.27-alpine AS runtime
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

### 빌드 속도 최적화 — 원격 빌드 캐시

모든 CI 빌드는 **원격 캐시**를 사용해 중복 빌드를 제거한다.

| 도구 | 캐시 유형 | 캐시 서버 |
|------|---------|---------|
| uv (Python) | GitHub Actions cache | `actions/cache` |
| Gradle (Java) | Gradle Build Cache | `build-cache.internal` |
| Turborepo (JS) | Remote Cache | `build-cache.internal` |
| Docker | BuildKit cache | GitHub Actions cache + Registry |

```yaml
# GitHub Actions — Docker BuildKit 레이어 캐시
- uses: docker/build-push-action@v5
  with:
    cache-from: type=gha
    cache-to: type=gha,mode=max
    build-args: BUILDKIT_INLINE_CACHE=1
```

## 백엔드 공통 구조 표준

### 레이어 구조 (언어 무관 공통)

```
서비스/
├── api/controller/    ← HTTP 입출력 (요청 검증, 응답 직렬화)
├── service/           ← 비즈니스 로직 (순수 함수/메서드)
├── repository/        ← 데이터 접근 (SQL, Redis, 외부 API)
├── domain/model/      ← 도메인 모델 (엔티티, 값 객체)
├── infrastructure/    ← 외부 연동 구현체 (DB 드라이버, HTTP 클라이언트)
└── config/            ← 환경설정
```

### 공통 원칙

| 원칙 | 내용 |
|------|------|
| 계층 간 단방향 의존 | api → service → repository (역방향 금지) |
| 외부 Mock 가능 구조 | 의존성 주입(DI)으로 모든 외부 의존 교체 가능 |
| 환경변수 타입 안전 | pydantic-settings (Python) / @ConfigurationProperties (Java) |
| 외부 호출 방어 | 타임아웃 + 재시도 + 서킷브레이커 (모든 외부 HTTP/DB 호출) |
| 입출력 계약 | 요청·응답 모델 명시 (Pydantic v2 / Jakarta Bean Validation) |

## 프론트엔드 공통 표준

### Enterprise Design System

팀별 독자 컴포넌트 라이브러리를 금지하고 **공용 Design System**을 사용한다.

```
@corp/design-system
├── components/          ← Button, Input, Table, Modal, Badge, Chart …
├── tokens/              ← Color, Typography, Spacing, Shadow
├── hooks/               ← useAuth, usePagination, useErrorHandler
└── layouts/             ← DashboardLayout, AuthLayout
```

- **Storybook**으로 컴포넌트 카탈로그 운영
- Design System 변경은 Design System 팀 PR → 제품 팀 소비

### 상태 관리 선택 기준

| 규모·복잡도 | 선택 |
|-----------|------|
| 단일 컴포넌트 | `useState`, `useReducer` |
| 페이지 수준 공유 | Context API |
| 앱 수준 공유 (단순) | Zustand |
| 앱 수준 공유 (복잡·대형) | Redux Toolkit |
| 서버 상태 동기화 | TanStack Query (React Query) |

## 마이크로서비스 분해 기준

| 기준 | 분리 신호 | 유지 신호 |
|------|----------|---------|
| 팀 소유권 | 2개 이상 팀이 같은 DB 수정 | 1개 팀이 소유 |
| 배포 주기 | 서로 다른 주기로 배포 필요 | 같은 주기 |
| 스케일링 | 특정 기능만 집중 스케일 필요 | 동일 스케일 |
| 기술 선택 | 다른 언어·프레임워크가 명확히 유리 | 동일 스택 |
| 장애 격리 | 한 기능 장애가 전체를 멈춰선 안 됨 | 허용 가능 |

> **모노리스 우선(Monolith First)**: 신규 서비스는 모노리스로 시작 후 위 기준 충족 시 분리.  
> 조기 마이크로서비스 분해는 복잡도만 증가시킨다.
