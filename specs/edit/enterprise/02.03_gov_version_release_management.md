# Enterprise Spec — 버전 및 릴리스 관리 (Version & Release Management)

> 조직 전체 **SW 버전, 릴리스 자동화, 이미지 태깅, CHANGELOG, 멀티서비스 조율 표준**을 정의한다.  
> 핵심: Conventional Commits → 자동 버전 결정 → CHANGELOG → 이미지 태깅 → 배포 승인.

---

## 버전 정책 (SemVer)

### 버전 체계

```
MAJOR.MINOR.PATCH[-PRERELEASE][+BUILD]

예시:
  1.2.3            — 정식 릴리스
  1.2.3-rc.1       — 릴리스 후보 (staging 검증 중)
  1.2.3-alpha.1    — 알파 (내부 테스트)
  2.0.0            — Breaking change 포함 Major 릴리스
```

### 버전 증가 규칙

| Conventional Commit | 버전 증가 | 예시 |
|--------------------|---------|------|
| `BREAKING CHANGE:` 또는 `feat!:` | `MAJOR` ↑ | 1.2.3 → 2.0.0 |
| `feat:` | `MINOR` ↑ | 1.2.3 → 1.3.0 |
| `fix:`, `perf:`, `refactor:` | `PATCH` ↑ | 1.2.3 → 1.2.4 |
| `docs:`, `test:`, `ci:`, `chore:` | 변경 없음 | — |

## 릴리스 자동화 (Semantic Release)

Conventional Commit 메시지를 분석해 **버전 결정 → CHANGELOG 생성 → Git Tag → 이미지 태깅 → 발행**을 자동화한다.

```
[main 머지]
  │
  ▼
semantic-release 분석
  ├─ Conventional Commit 파싱
  ├─ 버전 자동 결정 (MAJOR/MINOR/PATCH)
  ├─ CHANGELOG.md 자동 업데이트
  ├─ Git Tag 생성 (v1.3.0)
  ├─ GitHub Release 생성 (릴리스 노트 자동)
  ├─ 이미지 태그: ghcr.io/org/sp500-api:1.3.0
  └─ infra 저장소 values 자동 PR 생성
```

```json
// .releaserc.json — semantic-release 설정
{
  "branches": ["main"],
  "plugins": [
    "@semantic-release/commit-analyzer",
    ["@semantic-release/release-notes-generator", {
      "preset": "conventionalcommits",
      "presetConfig": {
        "types": [
          { "type": "feat",     "section": "✨ 새 기능" },
          { "type": "fix",      "section": "🐛 버그 수정" },
          { "type": "perf",     "section": "⚡ 성능 개선" },
          { "type": "refactor", "section": "♻️ 리팩터링", "hidden": true },
          { "type": "docs",     "section": "📚 문서", "hidden": true }
        ]
      }
    }],
    "@semantic-release/changelog",
    ["@semantic-release/exec", {
      "publishCmd": "docker tag ${nextRelease.version} ghcr.io/org/sp500-api:${nextRelease.version}"
    }],
    ["@semantic-release/github", { "assets": ["CHANGELOG.md"] }],
    "@semantic-release/git"
  ]
}
```

**GitHub Actions 릴리스 파이프라인**:

```yaml
# .github/workflows/release.yml
on:
  push:
    branches: [main]

jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write         # Git Tag·Release 생성
      packages: write         # GHCR 이미지 태깅
      id-token: write         # Cosign keyless 서명
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }   # 전체 히스토리 필요

      - name: Semantic Release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: npx semantic-release

      - name: Tag & Sign Docker Image
        if: env.NEW_RELEASE == 'true'
        run: |
          docker tag ghcr.io/org/sp500-api:${{ github.sha }} \
                     ghcr.io/org/sp500-api:${{ env.NEW_VERSION }}
          cosign sign --yes ghcr.io/org/sp500-api:${{ env.NEW_VERSION }}
```

## 이미지 태그 전략

| 태그 | 생성 시점 | 불변성 | 용도 |
|------|---------|--------|------|
| `{git-sha}` (예: `a1b2c3d`) | 모든 빌드 | ✅ 불변 | 배포 추적, 롤백 기준 |
| `{version}` (예: `1.3.0`) | semantic-release | ✅ 불변 | 릴리스 식별 |
| `{branch}-latest` (예: `main-latest`) | main 푸시마다 | ❌ 가변 | 개발 환경 참조용 |
| `latest` | 사용 금지 | ❌ 가변 | **금지** (추적 불가) |

```bash
# 권장 이미지 태그 조합 (CI)
IMAGE=ghcr.io/org/sp500-api

# 1. 불변 git-sha 태그 — 항상 생성
docker push ${IMAGE}:${GIT_SHA}

# 2. 릴리스 태그 — semantic-release가 생성
docker push ${IMAGE}:1.3.0

# 3. branch-latest — 개발 환경용 (prod에서 사용 금지)
docker push ${IMAGE}:main-latest
```

## 전사 SW 버전 카탈로그 관리

전사 SW 버전을 **단일 카탈로그로 통합 관리**한다. 서비스별 버전은 이 문서의 카탈로그가 단일 출처(Single Source of Truth)가 된다.

### 버전 카탈로그 업데이트 프로세스

```
Dependabot / Renovate Bot
  └─ 새 버전 감지 → PR 자동 생성
        │
        ▼
CI 검증 (테스트 통과, 보안 스캔)
        │
        ▼
자동 머지 (patch 버전) 또는 수동 리뷰 (minor/major)
        │
        ▼
versions.md 갱신 + 전사 공지 (Slack #tech-updates)
```

### Renovate 설정 (전사 공통)

```json
// renovate.json — 전사 기본 설정
{
  "extends": ["config:recommended"],
  "schedule": ["before 9am on monday"],
  "packageRules": [
    {
      "matchUpdateTypes": ["patch"],
      "automerge": true,                // patch 자동 머지
      "automergeType": "pr"
    },
    {
      "matchUpdateTypes": ["minor"],
      "automerge": false,               // minor 이상 수동 리뷰
      "reviewers": ["team:platform"]
    },
    {
      "matchPackageNames": ["python", "java", "node"],
      "matchUpdateTypes": ["major"],
      "labels": ["breaking-change", "needs-review"],
      "reviewers": ["team:architects"]  // major는 아키텍트 리뷰
    }
  ],
  "vulnerabilityAlerts": {
    "enabled": true,
    "automerge": true   // 보안 취약점 패치는 자동 머지
  }
}
```

## 멀티서비스 릴리스 조율

여러 서비스가 함께 배포되어야 할 때의 조율 기준.

### 서비스 간 의존성 버전 호환성

```yaml
# service-compatibility.yaml — 서비스 간 호환 매핑
services:
  sp500-api:
    version: "1.3.0"
    requires:
      sp500-frontend: ">=2.1.0"      # API 계약 Consumer
      mart-schema: ">=1.2.0"         # DB 스키마 버전
    provides:
      api-contract: "v1"
```

### 릴리스 트레인 (Release Train)

배포 주기가 맞는 서비스는 **릴리스 트레인**으로 묶어 함께 배포한다.

```
릴리스 트레인 v2026.05.03
  ├─ sp500-api: 1.3.0
  ├─ sp500-frontend: 2.2.0
  └─ airflow-dags: 1.1.5

배포 순서:
  1. DB 마이그레이션 (있는 경우)
  2. sp500-api (하위 호환 버전 먼저)
  3. sp500-frontend
  4. airflow-dags (가장 마지막)
```

## 롤백 버전 관리

```bash
# 현재 prod 배포 버전 확인
kubectl get deployment sp500-api -n prod \
  -o jsonpath='{.spec.template.spec.containers[0].image}'
# ghcr.io/org/sp500-api:1.3.0 (= git-sha: a1b2c3d)

# 특정 버전으로 즉시 롤백
kubectl set image deployment/sp500-api \
  api=ghcr.io/org/sp500-api:1.2.4 -n prod

# GitOps 방식 롤백 (권장)
# infra 저장소에서 values-prod.yaml의 image.tag를 이전 버전으로 PR → ArgoCD 동기화
git revert <commit> && git push  # ArgoCD가 자동 감지·반영
```

## API 버전과의 연계

서비스 버전(SemVer)과 API 버전(`/v1`, `/v2`)은 별개다.

| 상황 | 서비스 버전 | API 버전 |
|------|-----------|---------|
| 신기능 추가 (하위 호환) | MINOR ↑ | 유지 (`/v1`) |
| Breaking API 변경 | MAJOR ↑ | 신규 (`/v2`) + `/v1` 유지 6개월 |
| 버그 수정 | PATCH ↑ | 유지 |
