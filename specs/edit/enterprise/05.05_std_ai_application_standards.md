# Enterprise Spec — AI 애플리케이션 표준 (AI Application Standards)

> **조직 전체에서 AI를 안전하고 일관되게 개발·운영하는 표준**을 정의한다.  
> `13_llmops.md`(플랫폼 인프라)와 달리, 이 문서는 **AI 애플리케이션 설계 패턴**에 집중한다.

---

## AI 애플리케이션 분류

| 유형 | 설명 | 예시 |
|------|------|------|
| **단일 LLM 체인** | 프롬프트 → LLM → 응답 | 요약, 번역, 분류 |
| **단일 에이전트** | ReAct/CoT 루프, 툴 사용 | URL 탐색, 데이터 조회 |
| **멀티 에이전트** | 여러 에이전트 협업·위임 | 복잡한 워크플로우 |
| **RAG 애플리케이션** | 벡터 검색 + LLM 생성 | 문서 Q&A, 지식 검색 |
| **Human-in-the-Loop** | 사람의 승인·보정이 포함된 파이프라인 | 콘텐츠 검수, 법률 검토 |
| **Agentic Pipeline** | 자율 의사결정 + 외부 시스템 액션 | 자동 보고서 생성·발행 |

## 멀티 에이전트 패턴

### 패턴 1: Orchestrator-Worker

```
[Orchestrator Agent]
  ├─ 태스크 분해·계획
  ├─ Worker Agent 1 (데이터 수집)
  ├─ Worker Agent 2 (분석)
  └─ Worker Agent 3 (보고서 생성)
        │
  결과 집계·최종 응답
```

**적합한 상황**: 독립적으로 병렬 처리 가능한 하위 태스크가 명확할 때

```python
# LangGraph — Orchestrator-Worker
from langgraph.graph import StateGraph, END

def build_analysis_graph():
    graph = StateGraph(AnalysisState)

    graph.add_node("orchestrator", orchestrator_agent)
    graph.add_node("data_collector", data_collector_agent)
    graph.add_node("analyzer", analyzer_agent)
    graph.add_node("reporter", reporter_agent)

    graph.set_entry_point("orchestrator")
    graph.add_edge("orchestrator", "data_collector")
    graph.add_edge("orchestrator", "analyzer")
    graph.add_edge("data_collector", "reporter")
    graph.add_edge("analyzer", "reporter")
    graph.add_edge("reporter", END)

    return graph.compile()
```

### 패턴 2: Sequential Pipeline (순차 체인)

```
입력
  → 에이전트 A (전처리·구조화)
  → 에이전트 B (분석·추론)
  → 에이전트 C (검증·품질 체크)
  → 에이전트 D (포맷·출력)
  → 결과
```

**적합한 상황**: 각 단계의 출력이 다음 단계의 입력인 선형 흐름

### 패턴 3: Supervisor-Specialist

```
[Supervisor Agent]
  ├─ 라우팅 결정 (어떤 Specialist가 처리할지)
  ├─ Finance Specialist
  ├─ Legal Specialist
  ├─ Technical Specialist
  └─ Generalist (해당 없을 때)
```

**적합한 상황**: 입력 유형에 따라 다른 전문 에이전트가 필요한 경우

## Human-in-the-Loop (HiTL)

AI 결과가 중요한 의사결정·외부 액션에 직결될 때 **사람의 검토 단계**를 필수로 둔다.

### HiTL 적용 기준

| AI 결과 유형 | HiTL 필요 여부 | 이유 |
|------------|-------------|------|
| 투자·재무 의사결정 | ✅ 필수 | 오류 시 금전적 손실 |
| 법적·계약 내용 | ✅ 필수 | 규정 위반 리스크 |
| 개인정보 포함 결정 | ✅ 필수 | 프라이버시 규정 |
| 공개 콘텐츠 발행 | ✅ 권장 | 브랜드 리스크 |
| 내부 참고 분석 | ⚠️ 선택 | 참고용, 재사용 쉬움 |
| 단순 분류·태깅 | ❌ 불필요 | 낮은 영향, 재처리 쉬움 |

### HiTL 구현 패턴 (Airflow + Slack Approval)

```python
# Airflow DAG — HiTL 예시
with DAG("ai_report_with_approval") as dag:

    generate = PythonOperator(
        task_id="generate_ai_report",
        python_callable=run_llm_pipeline,
    )

    request_approval = SlackAPIPostOperator(
        task_id="request_human_approval",
        channel="#ai-review",
        text="""
        AI 보고서가 생성됐습니다. 검토 후 승인해주세요.
        보고서: {{ ti.xcom_pull('generate_ai_report') }}
        승인: [링크] | 거부: [링크]
        """,
    )

    wait_approval = ExternalTaskSensor(  # 또는 커스텀 Approval 센서
        task_id="wait_for_approval",
        external_dag_id="approval_workflow",
        timeout=86400,  # 24시간 대기
    )

    publish = PythonOperator(
        task_id="publish_approved_report",
        python_callable=publish_to_mart,
    )

    generate >> request_approval >> wait_approval >> publish
```

## 책임 있는 AI (Responsible AI)

### 필수 적용 원칙

| 원칙 | 구현 방법 |
|------|----------|
| **투명성** | AI 생성 콘텐츠임을 UI에 명시 |
| **설명 가능성** | 주요 판단 근거(key_drivers, evidence)를 응답에 포함 |
| **면책 고지** | 투자·법률·의료 관련 응답에 면책문구 필수 |

| **데이터 최소화** | LLM 입력에 불필요한 PII 포함 금지 |

### 검색 품질 기준 (전사 공통)

| 지표 | 최소 기준 | 측정 도구 |
|------|---------|---------|
| Context Recall | ≥ 0.75 | ragas |
| Faithfulness | ≥ 0.85 | ragas |
| Answer Relevancy | ≥ 0.80 | ragas |
| 검색 지연시간 p95 | ≤ 500ms | OTel |

### 접근 제어 (RAG Security)

```python
# RAG 검색 시 사용자 역할 필터 적용
async def search_knowledge(
    query: str,
    user_roles: list[str],
    namespace: str,
) -> list[Document]:
    # Weaviate — 역할 기반 필터
    results = await vector_store.similarity_search(
        query=query,
        k=5,
        filters={
            "path": ["access_roles"],
            "operator": "ContainsAny",
            "valueText": user_roles,
        },
        namespace=namespace,
    )
    return results
```

## AI 에이전트 안전 기준

### 에이전트 권한 최소화

```python
# 에이전트 툴에 명시적 권한 범위 선언
AGENT_PERMISSIONS = {
    "sp500-trend-agent": {
        "read": ["mart_daily_key_index", "mart_sector_trend_analysis"],
        "write": ["mart_sector_trend_analysis"],   # 쓰기 범위 최소화
        "external_calls": ["openai_api"],           # 허용된 외부 호출만
        "forbidden": ["ods_*", "fact_*", "dim_*"],  # 원천 데이터 직접 접근 금지
    }
}
```

### 에이전트 실행 제한

| 파라미터 | 기준값 | 이유 |
|---------|--------|------|
| `max_iterations` | 10 | 무한 루프 방지 |
| `max_execution_time` | 120초 | API 타임아웃 방지 |
| `max_tokens_per_call` | 4,000 | 비용 제한 |
| `daily_call_limit` | 팀별 할당 | FinOps 연동 |
| `handle_parsing_errors` | True | 자동 재시도 |
| `fallback_response` | 정의 필수 | 실패 시 안전한 기본값 |

### 에이전트 감사 로그 필수 항목

```python
# 모든 에이전트 실행은 감사 로그 필수
@dataclass
class AgentAuditLog:
    agent_id: str              # 에이전트 식별자
    run_id: str                # 실행 추적 ID
    user_id: str | None        # 호출 사용자 (자동화 실행 시 None)
    service: str               # 호출 서비스
    input_summary: str         # 입력 요약 (PII 제거)
    output_summary: str        # 출력 요약 (PII 제거)
    llm_model: str
    input_tokens: int
    output_tokens: int
    cost_usd: float
    duration_sec: float
    status: str                # success | failed | timeout
    started_at: datetime
    ended_at: datetime
```
