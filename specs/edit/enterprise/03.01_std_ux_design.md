## 1. Design Token 표준

Design Token은 **디자인과 코드 간의 단일 진실 소스**다.  
두 워크플로우 모두 동일한 토큰 값을 사용한다. **정의 방법**만 다르다.

| 방법 | React-only | Figma 기반 |
|------|-----------|-----------|
| 토큰 정의 위치 | `tokens.ts` (코드 직접) | Figma Variables → Style Dictionary 자동 동기화 |
| 토큰 변경 주체 | 개발자 PR | 디자이너 Figma → CI 자동 PR |
| 상세 | `03.01.01` 참조 | `03.01.02` 참조 |

### 토큰 분류 체계 (공통)

```
Global Token        (원자값)
  └─ Alias Token    (의미 부여)
        └─ Component Token (컴포넌트 전용)

Global:    --color-blue-500: #3B82F6
Alias:     --color-primary: var(--color-blue-500)
Component: --button-bg: var(--color-primary)
```

### 색상 토큰 (Semantic Color)

| 토큰 | 용도 | Light | Dark |
|------|------|-------|------|
| `color.primary` | 주요 액션, 링크 | `blue-600` | `blue-400` |
| `color.success` | 성공, 긍정 (bullish) | `green-600` | `green-400` |
| `color.warning` | 경고 | `amber-500` | `amber-400` |
| `color.error` | 오류, 부정 (bearish) | `red-600` | `red-400` |
| `color.neutral` | 텍스트, 보더 | `gray-700` | `gray-300` |
| `color.surface` | 배경, 카드 | `white` | `gray-900` |
| `color.overlay` | 모달 배경 | `black/50` | `black/70` |

### 타이포그래피 토큰

| 토큰 | Size | Weight | Line-height | 용도 |
|------|------|--------|-------------|------|
| `text.display` | 36px | 700 | 1.2 | 히어로 제목 |
| `text.h1` | 28px | 700 | 1.3 | 페이지 제목 |
| `text.h2` | 22px | 600 | 1.4 | 섹션 제목 |
| `text.h3` | 18px | 600 | 1.4 | 카드 제목 |
| `text.body` | 16px | 400 | 1.6 | 본문 기본 |
| `text.small` | 14px | 400 | 1.5 | 보조 텍스트 |
| `text.caption` | 12px | 400 | 1.4 | 레이블, 캡션 |

**서체**: 한국어 `Pretendard`, 영문 `Inter`

### 간격 토큰 (8pt Grid)

```
spacing.1  = 4px    spacing.4  = 16px (기본 패딩)
spacing.2  = 8px    spacing.6  = 24px
spacing.3  = 12px   spacing.8  = 32px
                    spacing.12 = 48px
                    spacing.16 = 64px
```

> 모든 간격·크기·배치는 **4 또는 8의 배수**.

### 반응형 브레이크포인트

| `sm` 640px | `md` 768px | `lg` 1024px | `xl` 1280px | `2xl` 1536px |

## 2. Design System 거버넌스 (공통)

### 컴포넌트 분류

| 레벨 | 설명 | 예시 | 소유권 |
|------|------|------|--------|
| Primitive | 최소 단위 | Button, Icon, Badge | Design System 팀 |
| Compound | Primitive 조합 | Card, Modal, Dropdown | Design System 팀 |
| Pattern | 도메인 독립 레이아웃 | DataTable, Pagination | Design System 팀 |
| Feature | 도메인 종속 | TrendAnalysisCard | 제품 팀 (기여 가능) |

### 버전 정책

| 변경 유형 | 버전 | 예시 |
|----------|------|------|
| 신규 컴포넌트·Props 추가 | Minor ↑ | `1.2.0` |
| 버그·스타일 수정 | Patch ↑ | `1.2.1` |
| Breaking Change | Major ↑ | `2.0.0` |

> Major 변경 시 마이그레이션 가이드 필수. 이전 버전 6개월 유지.

## 3. 접근성 (WCAG 2.2 AA) — 공통 필수

| 원칙 | 핵심 요건 | 측정 |
|------|---------|------|
| **인식 가능** | 이미지 대체 텍스트, 색상만으로 정보 전달 금지, 명도 대비 4.5:1+ | axe-core |
| **운용 가능** | 키보드 접근 100%, 포커스 표시, Skip Navigation | 수동 검사 |
| **이해 가능** | 에러 메시지 명확, 레이블 연결 | 사용자 테스트 |
| **견고** | ARIA 올바른 사용, Semantic HTML, Screen Reader 호환 | NVDA/VoiceOver |

### 명도 대비 기준

| 요소 | 최소 대비율 |
|------|-----------|
| 일반 텍스트 (< 18px) | 4.5:1 |
| 큰 텍스트 (≥ 18px Bold) | 3:1 |
| UI 컴포넌트 (버튼 보더 등) | 3:1 |

### 키보드 인터랙션

| 키 | 동작 |
|----|------|
| `Tab` / `Shift+Tab` | 포커스 이동 |
| `Enter` / `Space` | 버튼·링크 활성화 |
| `Esc` | 모달·팝오버 닫기 |
| `Arrow` | 탭·리스트 내 이동 |

### 접근성 CI 게이트 (공통)

```yaml
- name: axe-core 접근성 검사
  run: pnpm axe-storybook --exit-zero-violations false --rules wcag2aa
```

> PR마다 자동 — `critical`/`serious` 위반 시 머지 차단.

## 4. 컴포넌트 상태 설계 원칙 (공통)

모든 인터랙티브 컴포넌트는 **아래 상태를 모두 설계**한다.  
Figma이든 React 코드든 동일하게 적용한다.

```
Default → Hover → Focus → Active → Disabled

데이터 표시 컴포넌트 추가:
  Loading (Skeleton) → Empty → Error → Success
```

```typescript
type ComponentState = 'idle' | 'loading' | 'success' | 'error' | 'empty';
```

### 빈 상태 (Empty State)

```
아이콘(48px) 또는 일러스트
제목:  "조회할 데이터가 없습니다"      ← 비기술적 문구
설명:  "날짜나 필터를 변경해보세요"
CTA:   [필터 초기화] (선택)
```

### 에러 상태

```
에러 아이콘
제목:  "데이터를 불러오지 못했습니다"
설명:  사용자 친화적 설명 (기술 에러 코드 금지)
CTA:   [다시 시도]
```

> **절대 금지**: "Error 500", "NullPointerException", "undefined" 노출

## 5. 모션·애니메이션 표준 (공통)

| 토큰 | 값 | 용도 |
|------|-----|------|
| `motion.instant` | 0ms | 즉각 반응 |
| `motion.fast` | 100ms | 마이크로 인터랙션 |
| `motion.normal` | 200ms | 컴포넌트 트랜지션 |
| `motion.slow` | 300ms | 페이지 전환, 모달 |
| `motion.deliberate` | 500ms | 온보딩, 강조 |

```css
/* prefers-reduced-motion 필수 대응 */
@media (prefers-reduced-motion: reduce) {
  *, ::before, ::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 8. UX 리서치 & 테스트 (공통)

| 질문 유형 | 방법 | 소요 | 시점 |
|----------|------|------|------|
| "사용자가 무엇을 원하는가?" | 인터뷰 (5명) | 2~3일 | 요건 정의 전 |
| "UI가 직관적인가?" | 게릴라 테스트 (5명) | 0.5일 | 프로토타입 후 |
| "어디서 막히는가?" | 사용성 테스트 (5~8명) | 2~5일 | Hi-fi 후 |
| "전반적 만족도?" | SUS 설문 (0~100점) | 1시간 | 릴리스 후 |

### UX 품질 KPI

| 지표 | 목표 |
|------|------|
| Task Success Rate | ≥ 90% |
| SUS Score | ≥ 70 |
| Error Rate | < 5% |
| LCP | < 2.5초 |
| CLS | < 0.1 |
