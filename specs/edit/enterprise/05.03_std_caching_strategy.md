# Enterprise Spec — 캐싱 전략 (Caching Strategy)

> 조직 전체 서비스가 일관된 **다층 캐싱 아키텍처·키 거버넌스·비용 정책**을 따르도록 정의한다.  
> `14_finops.md`의 비용 거버넌스, `11_sre_practices.md`의 SLO, `05_zero_trust_security.md`의 보안과 연계한다.

---

## 전사 캐싱 레이어 구조

```
[클라이언트]
    │  브라우저 캐시 (Cache-Control / ETag)
    ▼
[CDN]                       ← 정적 파일, 공개 API 응답 (CloudFront / Cloudflare)
    │  CDN Miss 시
    ▼
[API Gateway]               ← 공개 엔드포인트 응답 캐시 (60초)
    │  Cache Miss 시
    ▼
[애플리케이션 (Redis)]       ← LLM 결과, 세션, 자주 조회 데이터, Rate Limit 카운터
    │  Cache Miss 시
    ▼
[데이터베이스]               ← DB 결과 캐시 (선택적, 고비용 쿼리만)
```

## Redis 엔터프라이즈 배포 표준

### Standalone vs Cluster 선택 기준

| 항목 | Standalone | Redis Cluster | Redis Sentinel |
|------|-----------|--------------|---------------|
| 데이터 크기 | < 10GB | > 10GB | — |
| 가용성 요건 | 개발·소규모 | 프로덕션 HA | 프로덕션 Failover |
| 샤딩 | 없음 | 자동 샤딩 | 없음 |
| 운영 복잡도 | 낮음 | 높음 | 중간 |
| **전사 권장** | dev 환경 | prod (> 5GB) | prod (< 5GB) |

### 네임스페이스(논리적 분리)

하나의 Redis Cluster를 여러 서비스가 공유할 때 **키 접두사로 네임스페이스를 분리**한다.

```
{service}:{version}:{entity}:{identifier}

예시:
  sp500:v1:mart:sector:IT:20260501
  auth:v1:jwks:cache
  api-gw:v1:rate-limit:ip:192.168.1.1
  llm:v1:analysis:sp500:sector:IT
```

| 원칙 | 내용 |
|------|------|
| 서비스 접두사 필수 | 다른 서비스 키 충돌 방지 |
| 버전 포함 | 스키마 변경 시 `v1→v2`로 자동 무효화 |
| 길이 제한 | 256바이트 이하 |
| 특수문자 | `:` 구분자만 허용, 공백·`@` 금지 |

## TTL 정책 (전사 표준)

| 캐시 대상 | TTL | 갱신 방식 | 비용 등급 |
|----------|-----|---------|---------|
| LLM 분석 결과 | 7일 | 명시적 무효화 | 높음 (재생성 비용) |
| 외부 API 응답 (주가 등) | 거래일 종료까지 | 파이프라인 완료 후 무효화 | 중간 |
| DB 집계 쿼리 결과 | 1시간 | TTL 만료 자동 | 낮음 |
| 사용자 세션 | 30분 (Access Token 수명) | 갱신 시 연장 | 낮음 |
| JWKS 공개키 | 1시간 | TTL 만료 후 재조회 | 낮음 |
| Rate Limit 카운터 | 1분 / 1시간 | 윈도우 기반 자동 | 낮음 |
| CDN 정적 파일 | 1년 (`immutable`) | 파일명 해시 변경으로 무효화 | 없음 |
| CDN API 응답 | 60초 | `Cache-Control: max-age=60` | 낮음 |

## 캐시 패턴 표준

### Cache-Aside (권장 기본 패턴)

```python
# corp_platform_sdk/cache.py — 전사 공용 구현
from typing import Callable, TypeVar
import orjson, redis.asyncio as aioredis

T = TypeVar("T")

async def cached(
    redis: aioredis.Redis,
    key: str,
    ttl_seconds: int,
    fetch_fn: Callable[[], T],
    serializer=orjson.dumps,
    deserializer=orjson.loads,
) -> T:
    hit = await redis.get(key)
    if hit:
        return deserializer(hit)

    result = await fetch_fn()
    await redis.setex(key, ttl_seconds, serializer(result))
    return result

# 캐시 무효화 (파이프라인 완료 시)
async def invalidate_pattern(redis: aioredis.Redis, pattern: str):
    async for key in redis.scan_iter(pattern):
        await redis.delete(key)
```

### Write-Through (DB 쓰기와 캐시 동시 갱신)

```python
# DB 갱신 즉시 캐시 갱신 — 읽기 일관성이 중요한 경우
async def update_with_cache(entity_id: str, data: dict):
    await db.update(entity_id, data)
    cache_key = f"service:v1:entity:{entity_id}"
    await redis.setex(cache_key, TTL, orjson.dumps(data))
```

### Thundering Herd 방지

```python
# 동시 Cache Miss 시 중복 백엔드 호출 방지
import asyncio

_locks: dict[str, asyncio.Lock] = {}

async def cached_with_lock(redis, key: str, ttl: int, fetch_fn):
    hit = await redis.get(key)
    if hit:
        return orjson.loads(hit)

    lock = _locks.setdefault(key, asyncio.Lock())
    async with lock:
        # 잠금 획득 후 다시 확인 (다른 코루틴이 이미 채웠을 수 있음)
        hit = await redis.get(key)
        if hit:
            return orjson.loads(hit)
        result = await fetch_fn()
        await redis.setex(key, ttl, orjson.dumps(result))
        return result
```

## 캐시 무효화 전략

| 전략 | 방법 | 적합한 상황 |
|------|------|------------|
| TTL 만료 | 자연 만료 | 데이터 허용 지연이 있을 때 |
| 명시적 삭제 | 이벤트 발생 시 `DEL` / `SCAN+DEL` | 파이프라인 완료, 데이터 갱신 |
| 버전 키 교체 | 키에 `v1→v2` 변경 | 스키마 변경 시 전체 무효화 |
| 이벤트 기반 | Kafka 이벤트 → 캐시 무효화 핸들러 | 마이크로서비스 간 캐시 동기화 |

### Kafka 이벤트 기반 무효화 (멀티서비스)

```python
# 파이프라인 완료 이벤트 → 전사 캐시 무효화
# Kafka topic: platform.cache.invalidate

async def handle_cache_invalidation_event(event: dict):
    """
    event 형식:
    { "patterns": ["sp500:v1:mart:*", "sp500:v1:dw:*"],
      "trade_date": "2026-05-01" }
    """
    for pattern in event["patterns"]:
        await invalidate_pattern(redis, pattern)
    log.info("cache_invalidated", patterns=event["patterns"])
```

## 캐시 모니터링 표준

### 핵심 메트릭 (Prometheus)

```
# 전사 표준 메트릭명
cache_hit_total{service, cache_key_prefix}
cache_miss_total{service, cache_key_prefix}
cache_hit_ratio{service}              = hit / (hit + miss)
cache_evictions_total{service}
cache_memory_used_bytes{service}
redis_cluster_health{cluster}         # 0=unhuman, 1=ok
```

### 알림 기준

| 알림 | 조건 | 채널 |
|------|------|------|
| 캐시 히트율 급락 | `cache_hit_ratio < 0.5` (5분 기준) | Slack `#platform-alerts` |
| Redis 메모리 경고 | 사용률 > 80% | Slack `#platform-alerts` |
| Redis 연결 실패 | 연속 3회 실패 | PagerDuty |
| Cluster 노드 다운 | node_count < expected | PagerDuty |

### Degraded 모드 (Redis 장애 시)

```python
# Redis 장애 시 DB 직접 조회로 Degraded 운영
# — 캐시 없이 동작하도록 서비스 구현 필수

async def get_with_fallback(redis, key, ttl, fetch_fn):
    try:
        return await cached(redis, key, ttl, fetch_fn)
    except redis.RedisError as e:
        log.warning("cache_fallback", key=key, error=str(e))
        return await fetch_fn()   # DB 직접 조회
```

## FinOps 연계 — 캐시 비용 최적화

| 최적화 항목 | 방법 | 효과 |
|-----------|------|------|
| LLM 응답 캐싱 | 동일 입력 재요청 시 LLM 미호출 | 비용 90%↓ 가능 |
| CDN 캐시 히트율 향상 | TTL 증가 + 파일명 해시 전략 | 원본 서버 부하 감소 |
| Redis 메모리 절약 | 불필요 키 TTL 단축·삭제 배치 | 인스턴스 크기 축소 |
| 압축 저장 | LZ4/Snappy로 value 압축 | 메모리 30~50%↓ |
