# Enterprise Spec — 데이터 플랫폼 표준 (Data Platform Standards)

> **여러 팀이 데이터를 생산·공유·소비할 때의 조직 수준 데이터 플랫폼 표준**을 정의한다.  
> 핵심 개념: Data Mesh(도메인 소유권) + Data Contract(계약 기반 통합) + Data Catalog(전사 가시화)

---

## 전체 데이터 플랫폼 아키텍처

```
[데이터 생산자 팀 (Domain Teams)]
  Finance Team ──► 재무 데이터 Product
  Marketing Team ──► 마케팅 데이터 Product
  Data Platform Team ──► S&P 500 데이터 Product
        │
        │  Data Contract (스키마·SLA 계약)
        ▼
[Data Catalog (OpenMetadata)]
  ├─ 전사 데이터 계보 (Lineage)
  ├─ 데이터셋 검색·문서화
  ├─ 품질 지표 가시화
  └─ 접근 권한 관리
        │
        ▼
[Enterprise Storage Layer]
  ├─ Raw Zone      : S3 / GCS (원본 보존)
  ├─ ODS Zone      : PostgreSQL (정제·통합)
  ├─ DW Zone       : PostgreSQL / BigQuery (집계)
  └─ Mart Zone     : PostgreSQL (도메인별 최종)
        │
        ▼
[데이터 소비자]
  ├─ BI Dashboard (Metabase / Grafana)
  ├─ AI/LLM Agent (RAG, 분석)
  ├─ API 서비스 (앱 백엔드)
  └─ 분석가 (Ad-hoc SQL / Jupyter)
```

## Data Mesh — 도메인 데이터 소유권

### 원칙

| 원칙 | 내용 |
|------|------|
| **도메인 소유** | 데이터를 생산하는 팀이 파이프라인·품질·SLA까지 책임 |
| **Data as a Product** | 각 데이터셋은 소비자가 신뢰하고 사용할 수 있는 제품이어야 함 |
| **Self-serve Platform** | 플랫폼 팀은 파이프라인 인프라를 PaaS로 제공, 도메인 팀은 소비 |
| **Federated Governance** | 전사 표준(보안·품질·계보)은 중앙화, 구현은 도메인 팀에 위임 |

### 데이터 도메인 정의

| 도메인 | 소유팀 | 핵심 데이터셋 | SLA |
|--------|--------|-------------|-----|
| Market Data | Data Platform | `ods_stock_price_daily`, `fact_sector_daily` | 매 거래일 09:00 KST |
| Finance | Finance | `fact_revenue`, `dim_customer` | 매월 1일 06:00 |
| Marketing | Marketing | `fact_campaign_event`, `mart_acquisition` | 매일 06:00 |
| Engineering | SRE | `fact_service_metric`, `mart_error_budget` | 실시간 |

## Data Contract — 생산자·소비자 계약

### 계약 구조

모든 팀 간 데이터 공유는 **Data Contract**로 명시한다.  
계약 없이 타 팀의 DB/테이블에 직접 접근하는 것을 **금지**한다.

```yaml
# contracts/market-data/sp500_daily_price_v1.yaml
id: "market-data.sp500_daily_price.v1"
status: active               # active | deprecated | retired
version: "1.0.0"
owner:
  team: data-platform
  slack: "#data-platform"
  email: data-platform@corp.example.com

dataset:
  name: ods_stock_price_daily
  description: "S&P 500 구성 종목 일별 OHLCV 원본 데이터"
  location: "postgresql://app-db/sp500/ods_stock_price_daily"
  access_roles: [analyst, viewer, data-engineer]

schema:
  fields:
    - name: ticker
      type: TEXT
      nullable: false
      description: "종목 코드"
    - name: trade_date
      type: DATE
      nullable: false
      description: "거래일 (미국 동부시간 기준)"
    - name: close_price
      type: NUMERIC(12,4)
      nullable: false
    - name: volume
      type: BIGINT
      nullable: true

quality:
  completeness: ">= 98%"           # 전체 종목 중 수집 비율
  freshness: "<= 3h after market_close"
  null_rate:
    close_price: "0%"
    volume: "< 1%"

sla:
  availability: "99.5%"
  delivery_time: "거래일 09:00 KST 이내"
  retention: "3년"

changelog:
  - version: "1.0.0"
    date: 2026-05-01
    description: "초기 계약"
```

### 계약 위반 대응

| 위반 유형 | 감지 방법 | 대응 |
|----------|----------|------|
| 품질 기준 미달 | DQ 파이프라인 자동 체크 | Slack 알림 → 생산자 팀 3시간 내 대응 |
| SLA 지연 | Airflow 모니터링 | PagerDuty → 생산자 팀 On-call |
| 스키마 Breaking Change | CI `oasdiff` 유사 도구 | 소비자 팀 사전 통보 + 마이그레이션 기간 |
| 접근 제어 무단 변경 | Vault Audit Log | 즉시 보안팀 에스컬레이션 |

## Enterprise Airflow 배포 표준

### 실행 환경 선택

| 항목 | Self-hosted (K8s) | MWAA (AWS) | Astronomer |
|------|-----------------|------------|------------|
| 운영 부담 | 높음 | 낮음 | 낮음 |
| 비용 | 인프라 비용 | $300~/월 | $500~/월 |
| K8s 통합 | 완전 | 제한적 | 완전 |
| 보안 제어 | 완전 | 제한 | 제한 |
| **권장** | 온프레미스·엄격한 보안 | AWS 중심 조직 | 빠른 도입 |

**전사 기본**: Self-hosted + KubernetesExecutor (K8s 환경)

### KubernetesExecutor 구성

```yaml
# airflow/values-prod.yaml (Helm)
executor: KubernetesExecutor

config:
  core:
    max_active_tasks_per_dag: 16
    max_active_runs_per_dag: 1
    fernet_key: "${AIRFLOW_FERNET_KEY}"

  kubernetes_executor:
    namespace: airflow-prod
    worker_container_repository: ghcr.io/org/airflow-worker
    worker_container_tag: "1.2.0"
    delete_worker_pods: true          # 완료 즉시 Pod 삭제 (비용)
    delete_worker_pods_on_failure: false  # 실패 Pod는 디버깅 유지

  logging:
    remote_logging: true
    remote_base_log_folder: "s3://airflow-logs/"

resources:
  requests:
    cpu: "500m"
    memory: "1Gi"
  limits:
    cpu: "2000m"
    memory: "4Gi"
```

### DAG 코드 표준

```python
# 전사 DAG 공통 패턴 — corp-airflow-sdk 사용
from corp_airflow_sdk import create_dag, task, on_failure_notify
from corp_airflow_sdk.sensors import TradingDaySensor
from corp_airflow_sdk.quality import DQCheck

# 전사 표준: create_dag()로 공통 설정 자동 적용
# (owner 태그, catchup=False, max_active_runs=1, 실패 알림 등)
with create_dag(
    dag_id="load_raw_to_ods",
    schedule="30 7 * * 1-5",
    team="data-platform",              # FinOps 비용 귀속
    data_domain="market-data",         # Data Catalog 연계
    sla_minutes=120,                   # SLA 초과 시 자동 알림
) as dag:

    is_trading = TradingDaySensor(
        task_id="check_trading_day",
        calendar="XNYS",               # exchange_calendars 표준
    )

    @task(retries=3, retry_delay=300)
    def load_raw():
        ...

    @task
    def dq_check():
        DQCheck.run([
            ("close_price null rate", "< 1%"),
            ("ticker count",          "> 480"),
        ])

    @on_failure_notify(channel="#data-alerts")
    def pipeline():
        is_trading >> load_raw() >> dq_check()
```

### DAG 거버넌스

| 규칙 | 기준 |
|------|------|
| DAG ID 네이밍 | `{domain}_{layer}_{action}` (예: `market_ods_load`) |
| 태그 필수 | `team:`, `domain:`, `env:` 태그 3개 필수 |
| 재처리 단위 | 날짜 파티션 단위, 멱등 보장 |
| Secret 접근 | Airflow Connection · Variable (평문 금지) |
| 코드 위치 | 서비스 레포 `airflow/dags/` + GitOps 배포 |
| 테스트 | `airflow dags test` + pytest-airflow 단위 테스트 |

## dbt (data build tool) 도입 표준

### Airflow + dbt 역할 분리

```
Airflow (오케스트레이션)          dbt (SQL 변환)
──────────────────────────        ──────────────────
DAG 스케줄링                      모델 정의 (SELECT)
태스크 의존성 관리                 테스트 (schema.yml)
외부 시스템 연동                   문서화 (description)
재시도·알림                       계보 추적 (lineage graph)
        │                               │
        └─── Airflow가 dbt run 호출 ────┘
```

```python
# Airflow DAG에서 dbt 호출
from airflow.operators.bash import BashOperator

dbt_run = BashOperator(
    task_id="dbt_build_dw",
    bash_command="""
        dbt run --profiles-dir /opt/airflow/dbt_profiles \
                --target {{ var.value.env }} \
                --select mart_daily_key_index
    """,
)
```

### dbt 프로젝트 구조 표준

```
dbt/
├── models/
│   ├── staging/        ← ODS 원본 → 정규화·타입 변환 (1:1 대응)
│   │   └── stg_stock_price_daily.sql
│   ├── intermediate/   ← 중간 집계 (재사용 가능한 CTE)
│   │   └── int_sector_daily_agg.sql
│   └── marts/          ← 최종 Mart (비즈니스 사용자 대상)
│       └── mart_daily_key_index.sql
├── tests/
│   ├── generic/        ← not_null, unique, accepted_values
│   └── singular/       ← 커스텀 SQL 테스트
├── macros/             ← 재사용 가능한 Jinja 함수
├── seeds/              ← 정적 참조 데이터 (dim_sector CSV 등)
└── dbt_project.yml
```

```yaml
# dbt_project.yml 전사 표준 설정
name: corp_data
version: "1.0.0"

models:
  corp_data:
    staging:
      +materialized: view           # staging은 뷰
      +tags: ["staging"]
    intermediate:
      +materialized: ephemeral      # 중간 모델은 CTE로 인라인
    marts:
      +materialized: table          # Mart는 물리 테이블
      +tags: ["mart"]
      +post-hook: "GRANT SELECT ON {{ this }} TO ROLE analyst"  # 권한 자동 부여

# 전사 공통 테스트 — 모든 모델 자동 적용
tests:
  - not_null:
      column_name: created_at
  - dbt_utils.recency:             # freshness 자동 검증
      datepart: hour
      field: created_at
      interval: 25
```

## Data Catalog (OpenMetadata)

### 자동 메타데이터 수집

```yaml
# openmetadata/connectors/postgresql-sp500.yaml
source:
  type: databaseService
  serviceName: sp500-postgresql
  serviceConnection:
    config:
      type: Postgres
      hostPort: "app-db:5432"
      database: sp500
  sourceConfig:
    config:
      markDeletedTables: true
      includeTables: true
      includeViews: true
      lineageInformation:
        dbServiceNames: ["sp500-postgresql"]

processor:
  type: orm-profiler            # 컬럼별 통계 자동 수집
  config:
    tableConfig:
      - fullyQualifiedName: "sp500-postgresql.sp500.ods_stock_price_daily"
        profileSample: 30       # 30% 샘플링

sink:
  type: metadata-rest
  config:
    api_endpoint: "https://catalog.internal/api/v1"
```

### Catalog 활용 기준

| 활용 | 방법 |
|------|------|
| 데이터셋 검색 | OpenMetadata 검색 UI |
| 계보 추적 | 자동 수집 (dbt lineage + Airflow) |
| 품질 지표 확인 | Profiler 결과 + DQ 테스트 결과 |
| 소유권·연락처 | 팀·Slack 채널 등록 필수 |
| 접근 요청 | Catalog UI → 소유팀 승인 워크플로 |

## 데이터 보안 표준

### 열 수준 보안 (Column-Level Security)

```sql
-- PostgreSQL 열 마스킹 뷰 (L4 데이터 접근 제어)
CREATE VIEW ods_stock_price_daily_masked AS
SELECT
    ticker,
    trade_date,
    CASE
        WHEN current_user IN (SELECT username FROM data_access_roles WHERE role = 'analyst')
        THEN close_price
        ELSE NULL          -- viewer는 종가 미노출
    END AS close_price,
    volume
FROM ods_stock_price_daily;

-- 행 수준 보안 (Row-Level Security)
ALTER TABLE mart_sector_trend_analysis ENABLE ROW LEVEL SECURITY;
CREATE POLICY analyst_policy ON mart_sector_trend_analysis
    FOR SELECT TO analyst
    USING (true);                  -- analyst는 전체 접근

CREATE POLICY viewer_policy ON mart_sector_trend_analysis
    FOR SELECT TO viewer
    USING (sentiment IS NOT NULL); -- viewer는 분석 완료 행만
```

### 데이터 분류별 파이프라인 처리

| 등급 | 처리 기준 | 로그 정책 | 접근 제어 |
|------|---------|---------|---------|
| L1 공개 | 일반 처리 | 전체 로그 허용 | 인증된 사용자 전체 |
| L2 내부 | 일반 처리 | 필드 선택적 로그 | 역할 기반 |
| L3 기밀 | 암호화 저장 | PII 마스킹 후 로그 | 최소 권한 |
| L4 PII | 암호화 + 마스킹 | 로그 금지 | 개인별 접근 승인 |

## 파이프라인 테스트 표준

### 테스트 레이어

```
단위 테스트 (pytest)
  ├─ DAG Task 함수 단위 (외부 Mock)
  ├─ dbt 모델 컴파일 검사
  └─ DQ 규칙 함수 테스트

통합 테스트 (Testcontainers)
  ├─ 실 PostgreSQL + 샘플 데이터
  ├─ dbt run + dbt test
  └─ DAG end-to-end (소규모 데이터)

데이터 품질 테스트 (운영 중 상시)
  ├─ Great Expectations 또는 dbt tests
  ├─ 임계치 초과 시 DAG fail + 알림
  └─ 결과를 pipeline_dq_log에 기록
```

### dbt 테스트 표준

```yaml
# models/schema.yml
models:
  - name: mart_daily_key_index
    description: "Sector 일별 주요 지표"
    columns:
      - name: sector_id
        tests:
          - not_null
          - relationships:            # 참조 무결성
              to: ref('dim_sector')
              field: sector_id
      - name: rsi_14
        tests:
          - not_null
          - dbt_utils.accepted_range: # RSI는 0~100
              min_value: 0
              max_value: 100
      - name: trade_date
        tests:
          - not_null
          - dbt_utils.recency:
              datepart: day
              field: trade_date
              interval: 3             # 3일 이상 미갱신 시 실패
    tests:
      - dbt_utils.unique_combination_of_columns:
          combination_of_columns: [trade_date, sector_id]
```

## FinOps for Data Pipeline

### 파이프라인 비용 태그

```python
# 전사 DAG 공통 태그 (FinOps 연계)
with create_dag(
    dag_id="build_dw_sector",
    team="data-platform",          # Kubernetes label → 비용 집계
    data_domain="market-data",
    cost_center="CC-1234",
) as dag:
    ...

# KubernetesExecutor Pod에 자동 label 주입
# → OpenCost가 팀·도메인별 파이프라인 비용 집계
```

### 비용 최적화 기준

| 항목 | 기준 | 방법 |
|------|------|------|
| Worker Pod 크기 | 태스크 실제 사용량 기반 설정 | VPA 권장값 주간 검토 |
| 불필요 재시도 비용 | 재시도 간격 지수 백오프 | `retry_delay` 최소 5분 |
| 야간 Dev 파이프라인 | 비거래일 자동 skip | TradingDaySensor 필수 |
| 원격 스토리지 비용 | Parquet 압축 + 파티셔닝 | Snappy 압축, 일별 파티션 |
| DQ 프로파일링 | 샘플링 비율 조정 | 대형 테이블 10~30% |
