# Enterprise Spec — Platform Engineering (IDP / Golden Path)

> **플랫폼 팀이 제공하는 자기완결형 개발자 경험(IDP)**을 조직 표준으로 정의한다.  
> 핵심 개념: 제품 팀은 "무엇을(what)"만 결정하고, 플랫폼 팀이 "어떻게(how)"를 제공한다.

---

## Internal Developer Platform (IDP) 개요

```
[개발자]
  └─ Backstage (셀프서비스 포털)
        ├─ Software Catalog   → 전사 서비스·API·팀·리소스 등록
        ├─ Golden Path Template → 표준 프로젝트 스캐폴딩 (클릭 1번)
        ├─ Tech Radar         → 조직 기술 채택/평가/철수 현황
        ├─ TechDocs           → Markdown 기반 문서 자동 발행
        └─ Plugin Ecosystem   → CI 상태, 비용, SLO, 보안 취약점 통합 뷰

[플랫폼 팀이 제공]
  ├─ Paved Road (운영 검증된 기본 경로)
  │   ├─ FastAPI / Spring Boot 서비스 템플릿
  │   ├─ React SPA 템플릿
  │   ├─ Airflow DAG 프로젝트 템플릿
  │   └─ LLM Agent 서비스 템플릿
  ├─ Shared Infrastructure (공용 인프라)
  │   ├─ PostgreSQL, Redis, Kafka (PaaS 형태)
  │   ├─ OTel Collector, Grafana, OpenSearch
  │   └─ Keycloak (Multi-Realm 운영)
  └─ GitOps 클러스터 (ArgoCD) — 배포 자동화
```

## Golden Path 정의

### Golden Path 원칙

| 원칙 | 내용 |
|------|------|
| Paved Road | 기본 경로를 따르면 보안·관측성·CI/CD가 자동 포함 |
| Opt-out, not opt-in | 표준 적용은 기본값. 벗어날 때만 승인·이유 명시 |
| Self-service | 플랫폼 팀 티켓 없이 개발자가 직접 서비스 생성 |
| Feedback loop | 개발자가 템플릿 개선을 PR로 기여 가능 |

### 서비스 템플릿 (Backstage Software Template)

```yaml
# template.yaml (Backstage)
apiVersion: scaffolder.backstage.io/v1beta3
kind: Template
metadata:
  name: fastapi-service-template
  title: FastAPI 서비스 (표준)
spec:
  parameters:
    - title: 서비스 기본 정보
      properties:
        name: { type: string, description: "서비스 이름 (소문자-하이픈)" }
        owner: { type: string, description: "팀 이름" }
        description: { type: string }
  steps:
    - id: fetch-template
      action: fetch:template
      input:
        url: ./skeleton   # 표준 프로젝트 구조 복사
    - id: create-repo
      action: github:repo:create
      input:
        name: ${{ parameters.name }}
        org: ${{ parameters.org }}
    - id: register-catalog
      action: catalog:register  # Backstage Software Catalog 자동 등록
  output:
    links:
      - title: GitHub Repo
        url: ${{ steps.create-repo.output.remoteUrl }}
```

### 템플릿이 포함하는 것 (자동 제공)

| 카테고리 | 포함 항목 |
|---------|---------|
| CI | GitHub Actions: lint, test, build, SAST, SBOM |
| 관측성 | OTel SDK 계측, structlog, Prometheus `/metrics` |
| 보안 | Dependabot, Trivy 이미지 스캔, Cosign 서명 |
| 배포 | ArgoCD Application manifest, Helm chart 기본값 |
| 문서 | `docs/` + `mkdocs.yml` → TechDocs 자동 발행 |
| 테스트 | pytest + testcontainers, 커버리지 80% 게이트 |

## 플랫폼 팀 운영 모델

### 제품 팀 vs 플랫폼 팀 책임 분리

| 항목 | 제품 팀 | 플랫폼 팀 |
|------|---------|----------|
| 비즈니스 로직 | ✅ 직접 소유 | — |
| 서비스 SLO 정의 | ✅ 직접 정의 | — |
| Helm values 커스터마이징 | ✅ 제한 범위 | — |
| CI/CD 파이프라인 수정 | ⚠️ PR + 승인 필요 | ✅ 표준 소유 |
| K8s 클러스터 설정 | ❌ 직접 불가 | ✅ 직접 소유 |
| 공용 인프라 (DB, Redis) | ❌ 직접 불가 | ✅ PaaS 형태 제공 |
| 보안 정책 (OPA/Kyverno) | ❌ 직접 불가 | ✅ 직접 소유 |

### Platform SLO

플랫폼 자체도 SLO를 갖는다.

| 항목 | SLO |
|------|-----|
| 새 서비스 스캐폴딩 → PR ready | 10분 이내 |
| ArgoCD 배포 반영 (Sync) | 5분 이내 |
| Shared DB 프로비저닝 | 15분 이내 (자동화) |
| 플랫폼 가용성 | 99.9% 이상 |
