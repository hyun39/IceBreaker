# Enterprise Spec — UX 설계: Figma 기반 워크플로우

> **디자이너가 소스, 코드가 구현이다.**  
> Figma에서 정의한 디자인이 토큰·컴포넌트·핸드오프를 통해 코드로 이식되는 워크플로우.  
> 공통 기준(`03.01_std_ux_design.md`)을 먼저 읽은 후 이 문서를 적용한다.

---

## 언제 이 워크플로우를 선택하는가

| 조건 | 이유 |
|------|------|
| 전문 UX/UI 디자이너가 팀에 있다 | 디자이너의 도구에서 작업 |
| 외부 고객 제품, 강한 브랜드 아이덴티티 | 시각적 정확도가 핵심 |
| 복잡한 인터랙션·애니메이션·일러스트 | Figma Prototype이 효과적 |
| 디자이너·개발자 역할 분리가 명확한 조직 | 핸드오프 프로세스가 필요 |
| Design System 초기 구축 | Figma Variables → 토큰 → 코드 파이프라인 설정 |

---

## 전체 워크플로우

```
[요건 · 유저스토리]
        │
        ▼ 디자이너
[L1 Figma 와이어프레임]  ← Lo-fi, 흐름·레이아웃 검증
  팀 리뷰 (Figma 댓글)
        │  피드백 반영
        ▼ 디자이너
[L2 Figma Hi-fi]         ← Figma Variables 토큰 적용, 상태별 프레임
  이해관계자 승인 (Figma Prototype 클릭)
  게릴라 테스트 (3~5명)
        │  승인 + DoR 통과
        ▼ 자동화 (CI)
[Design Token PR]         ← Figma Variables → Style Dictionary → tokens.css
        │  머지
        ▼ 개발자
[React 구현]              ← @corp/design-system + Figma Dev Mode 참조
  Storybook 스토리 작성
  Chromatic 시각적 회귀 검사
        │
        ▼
[프로덕션 배포]
```

## Design Token 정의 (Figma Variables → 코드 자동화)

Figma Variables가 **단일 진실 소스**다. 코드의 토큰은 Figma에서 자동 동기화된다.

### 자동화 파이프라인

```
[Figma]
  Variables 수정 (디자이너)
        │
        ▼ CI (매일 00:00 또는 PR 트리거)
[Figma API 폴링]
  python scripts/fetch_figma_tokens.py
        │  변경 감지
        ▼
[Style Dictionary 변환]
  npx style-dictionary build
        │
        ▼
[자동 PR 생성]
  "chore: sync design tokens from Figma (2026-05-03)"
  변경된 토큰 diff 포함
        │  개발자 리뷰·머지
        ▼
[패키지 배포]
  @corp/design-system Patch 릴리스
```

### Figma Variable 구조

```
📁 Collections
  📁 Color / Global       ← blue-500, gray-900 등 원자값
  📁 Color / Semantic     ← primary, success, error (Mode: Light/Dark)
  📁 Spacing              ← spacing-4 = 16
  📁 Typography           ← text-body-size = 16, text-body-weight = 400
  📁 Motion               ← motion-normal = 200
```

```python
# scripts/fetch_figma_tokens.py
import httpx, json

FIGMA_FILE_ID = "..."
FIGMA_TOKEN = os.environ["FIGMA_TOKEN"]

def fetch_variables():
    resp = httpx.get(
        f"https://api.figma.com/v1/files/{FIGMA_FILE_ID}/variables/local",
        headers={"X-Figma-Token": FIGMA_TOKEN},
    )
    variables = resp.json()["meta"]["variables"]
    tokens = {}
    for var_id, var in variables.items():
        collection = var["variableCollectionId"]
        name  = var["name"].lower().replace("/", ".").replace(" ", "-")
        value = var["valuesByMode"][DEFAULT_MODE_ID]
        tokens[name] = value
    json.dump(tokens, open("tokens.json", "w"), indent=2)
```

### Style Dictionary 설정

```javascript
// style-dictionary.config.js
module.exports = {
  source: ['tokens.json'],
  platforms: {
    css: {
      transformGroup: 'css',
      prefix: '',
      buildPath: 'dist/',
      files: [{ destination: 'tokens.css', format: 'css/variables' }],
    },
    js: {
      transformGroup: 'js',
      buildPath: 'dist/',
      files: [{ destination: 'tokens.js', format: 'javascript/es6' }],
    },
    tailwind: {
      transformGroup: 'js',
      buildPath: 'dist/',
      files: [{ destination: 'tailwind.tokens.json', format: 'json/flat' }],
    },
  },
};
```

## Figma 파일 구조 표준

모든 프로젝트의 Figma 파일은 아래 구조를 따른다.

```
📁 [프로젝트명] — Design  (팀 공유 파일)
  📄 00_Cover
      프로젝트명 · 버전 · 담당 디자이너 · 최종 수정일
  📄 01_Design Tokens
      Figma Variables 연결 확인용 스타일 가이드
  📄 02_Component Library
      이 프로젝트 전용 컴포넌트 (Design System에 없는 것)
  📄 03_User Flows
      시나리오별 화면 전환 흐름도
  📄 04_Wireframes (Lo-fi)
      회색 박스 기반 레이아웃 · 정보 구조
  📄 05_Designs (Hi-fi)
      Figma Variables 토큰 적용 · 상태별 프레임
      ├─ Default / Hover / Focus / Active / Disabled
      └─ Loading / Empty / Error / Success
  📄 06_Prototype
      클릭 가능한 인터랙티브 프로토타입
  📄 07_Handoff Notes
      개발자 전달 사항 · 애니메이션 스펙 · 에셋 목록
```

### Figma Component 설계 원칙

```
컴포넌트 이름: 파스칼케이스 (Button, TrendCard)
Variant 구조:
  Property: state   → default / hover / loading / empty / error
  Property: theme   → light / dark
  Property: size    → sm / md / lg (필요 시)

Auto Layout 필수:
  - 모든 컴포넌트는 Auto Layout 적용 (flex 방향 명시)
  - 고정 크기 금지 → Hug Contents / Fill Container

Figma Variables 필수:
  - 색상·간격·타이포는 반드시 Variables 연결
  - 하드코딩 금지 (#3B82F6 직접 입력 금지)
```

## 디자인 리뷰 프로세스

### Lo-fi (L1) 리뷰

```
디자이너: 와이어프레임 완성 → Figma 링크 공유
        │
팀 비동기 리뷰 (Figma 댓글)
  체크 포인트:
  ├─ 화면 목록이 유저스토리를 모두 커버하는가?
  ├─ 네비게이션 흐름이 자연스러운가?
  └─ 빠진 상태(에러/빈/로딩)가 있는가?
        │  피드백 반영
        ▼
Hi-fi 진행 승인
```

### Hi-fi (L2) 공식 승인

```
디자이너: Hi-fi 완성 → Prototype 링크 생성
        │
이해관계자 승인 세션
  체크 포인트:
  ├─ [ ] 모든 상태(loading/empty/error/success) 프레임 존재
  ├─ [ ] Figma Variables 토큰만 사용 (하드코딩 없음)
  ├─ [ ] 접근성 대비율 4.5:1+ (Figma A11y Plugin 통과)
  ├─ [ ] 모바일·다크 모드 프레임 존재
  ├─ [ ] 면책문구·법적 고지 반영 (금융 도메인)
  └─ [ ] 이해관계자 서명 (또는 Figma Comment "Approved")
        │
        ▼
개발 착수 (DoR 진입)
```

## 핸드오프 (Figma → 개발자)

### Figma Dev Mode 활용

```
개발자가 Figma Dev Mode에서 확인:
  ├─ CSS 속성 자동 표시 (padding, font-size, border-radius …)
  ├─ Design Token 연결 확인 (--color-primary 등 변수명 표시)
  ├─ 에셋 Export (SVG, PNG 1x/2x)
  └─ 컴포넌트 Props 힌트
```

### 핸드오프 체크리스트

**디자이너 준비:**
- [ ] 모든 레이어에 의미 있는 이름 부여 (Button/Primary, Card/Trend)
- [ ] Auto Layout 적용 확인
- [ ] Figma Variables 연결 확인
- [ ] 에셋 Export 설정 완료 (1x, 2x, SVG)
- [ ] 07_Handoff Notes 페이지에 애니메이션 스펙 기록
- [ ] Storybook 스토리 생성 범위 개발팀과 합의

**개발자 수행:**
- [ ] Figma Dev Mode에서 토큰 매핑 확인
- [ ] `@corp/design-system` 컴포넌트로 구현 (커스텀 CSS 최소화)
- [ ] 4가지 상태 Storybook 스토리 작성
- [ ] Chromatic 시각적 회귀 검사

## Figma → Storybook 시각적 비교

구현 완료 후 디자인과 코드의 시각적 일치를 검증한다.

```typescript
// Storybook에 Figma URL 링크 추가 (chromatic-storybook-figma 플러그인)
const meta: Meta<typeof TrendAnalysisCard> = {
  title: 'Feature/TrendAnalysisCard',
  component: TrendAnalysisCard,
  parameters: {
    design: {
      type: 'figma',
      url: 'https://www.figma.com/file/XXX/...',  // 해당 컴포넌트 프레임 URL
    },
  },
};
```

Storybook 패널에서 Figma 디자인과 구현 코드를 나란히 비교한다.

## 디자이너·개발자 협업 규칙

| 상황 | 규칙 |
|------|------|
| 디자인과 구현이 다를 때 | 이슈 생성 → 우선순위 합의 → Figma 또는 코드 수정 결정 |
| 새 컴포넌트 필요 | 디자이너 Figma 설계 → Design System 팀 리뷰 → 코드 구현 순서 |
| 긴급 핫픽스 | 코드 먼저 수정 → 24시간 내 Figma 동기화 |
| 토큰 변경 | Figma Variables 수정 → CI PR → 개발자 승인 |

| 성능 측정 | **Lighthouse CI** | LCP·CLS |
