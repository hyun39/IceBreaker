# Enterprise Spec — 실행 가능한 스펙 (Executable Specification)

> **핵심**: Gherkin 인수기준이 문서로만 존재하는 것이 아니라 CI에서 실제로 실행된다.  
> 스펙이 통과하면 기능이 올바른 것이고, 실패하면 코드 또는 스펙이 잘못된 것이다.  
> `01.01_gov_business_requirements.md`의 Gherkin 작성 기준과 연계한다.

---

## 왜 Executable Specification인가

```
현재 (Level 3)                      Level 4 목표
─────────────────                    ───────────────────────────
Gherkin 인수기준 → 문서에만 존재      Gherkin → CI에서 자동 실행
개발자가 수동으로 AC 확인             AC 실패 = PR 머지 차단
"스펙을 만족하는가?" 사람이 판단      "스펙을 만족하는가?" 기계가 검증
```

```python
# tests/bdd/steps/mart_trend_steps.py
from pytest_bdd import given, when, then, parsers
from fastapi.testclient import TestClient

@given("거래일 {date}의 파이프라인이 완료된 상태이고")
def pipeline_completed(date: str, test_db, seed_mart_data):
    seed_mart_data(date)   # 픽스처 적재

@given("사용자가 analyst 역할로 인증되어 있다")
def analyst_authenticated(client, analyst_token):
    client.headers.update({"Authorization": f"Bearer {analyst_token}"})

@when(parsers.parse("GET {path} 을 호출하면"))
def call_api(path: str, client, response_holder):
    response_holder["resp"] = client.get(path)

@then(parsers.parse("응답 코드는 {code:d}이어야 한다"))
def check_status(code: int, response_holder):
    assert response_holder["resp"].status_code == code

@then("응답에 11개 Sector 분석이 포함되어야 한다")
def check_sector_count(response_holder):
    data = response_holder["resp"].json()
    assert len(data["analyses"]) == 11

@then("응답에 disclaimer_ko 필드가 포함되어야 한다")
def check_disclaimer(response_holder):
    data = response_holder["resp"].json()
    for analysis in data["analyses"]:
        assert "disclaimer_ko" in analysis
        assert len(analysis["disclaimer_ko"]) > 0
```

## CI 통합 (GitHub Actions)

```yaml
# .github/workflows/ci.yml에 추가

  bdd-test:
    runs-on: ubuntu-latest
    needs: [unit-test]
    services:
      postgres:
        image: postgres:15
        env: { POSTGRES_PASSWORD: test }
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v3

      - name: Run BDD Tests (Behave)
        run: |
          uv run pytest tests/bdd/ \
            --gherkin-terminal-reporter \
            --spec-coverage-report=spec_coverage.json \
            -v
        env:
          DATABASE_URL: postgresql://postgres:test@localhost/test

      - name: Publish Spec Coverage Report
        uses: actions/upload-artifact@v4
        with:
          name: spec-coverage
          path: spec_coverage.json

      - name: Comment Spec Coverage on PR
        uses: actions/github-script@v7
        with:
          script: |
            const coverage = require('./spec_coverage.json');
            github.rest.issues.createComment({
              body: `## 📋 Spec Coverage\n
              | 지표 | 값 |
              |------|-----|
              | 총 시나리오 수 | ${coverage.total} |
              | 통과 | ${coverage.passed} |
              | 실패 | ${coverage.failed} |
              | 커버리지 | ${coverage.percentage}% |`
            });
```

## Spec Coverage 측정

스펙 커버리지 = **"유저스토리 중 BDD로 검증된 비율"**

```python
# scripts/spec_coverage.py
# business_spec.md의 AC 항목 수 vs features/*.feature 시나리오 수 비교

import re, json, glob

def count_acceptance_criteria(spec_file: str) -> int:
    """business_spec.md에서 AC-NNN 패턴 개수 추출"""
    text = open(spec_file).read()
    return len(re.findall(r"AC-\d{3}", text))

def count_bdd_scenarios(feature_dir: str) -> int:
    """*.feature 파일의 Scenario 수 합산"""
    total = 0
    for f in glob.glob(f"{feature_dir}/**/*.feature", recursive=True):
        total += open(f).read().count("Scenario:")
    return total

ac_count  = count_acceptance_criteria("specs/business_spec.md")
bdd_count = count_bdd_scenarios("features/")
coverage  = round(bdd_count / ac_count * 100, 1) if ac_count else 0

result = {
    "total": ac_count,
    "covered": bdd_count,
    "percentage": coverage,
    "passed": 0,  # pytest 실행 후 채워짐
    "failed": 0,
}
json.dump(result, open("spec_coverage.json", "w"))
print(f"Spec Coverage: {coverage}% ({bdd_count}/{ac_count})")
```

### 커버리지 목표

| 단계 | 목표 | 의미 |
|------|------|------|
| 초기 도입 | ≥ 50% | Happy Path + 주요 예외 |
| 성숙 단계 | ≥ 80% | 대부분의 AC 커버 |
| 우수 | ≥ 95% | 엣지 케이스 포함 |
